<summary><strong>💡추천 엔진 아이디어: S-O-V 구조로 추천 엔진 만들기</strong></summary>

- S-O-V(주/목/서) 구조로 파싱하여 추천 엔진을 만들 때, 데이터의 `일상성`과 `라벨링의 정교함`이 핵심이 됨

- 아이트래킹 기반의 9~12분할 UI 환경에서 **S-O-V(주어-목적어-서술어)** 추천 엔진을 구축하는 과정은 일반적인 챗봇과는 결이 다름. 사용자의 '시선 피로도'를 최소화하기 위해 **확률적으로 가장 높은 후보**를 먼저 제안하는 것이 핵심.

---

엔진 구축 과정을 4단계로 나누면:

### **1단계: 데이터 전처리 및 트리플렛(Triplet) 추출**

먼저 수집한 한국어 데이터셋(예: AI 허브 감성 대화)을 **[감정 - 주어(S) - 목적어(O) - 서술어(V)]**의 구조로 정형화=

1. **KoNLPy(Mecab 추천) 활용**: 한국어는 어미 변화가 심하므로 형태소 분석기를 통해 단어의 **원형(Lemma)** 추출
    - `NNG(일반명사)`, `NNP(고유명사)` → 주어(S) 및 목적어(O) 후보
    - `VV(동사)`, `VA(형용사)` → 서술어(V) 후보
2. **데이터 정제**: "어제 손주가 와서 너무 좋았다"라는 문장이 있다면, 다음과 같이 핵심 요소만 남김
    - **Input**: "어제 손주가 와서 너무 좋았다" (감정: 기쁨)
    - **Output**: `[기쁨] - [손주] - [오다] - [좋다]` (S-O-V 트리플렛 생성)

### **2단계: 조건부 확률 모델 설계**

사용자가 특정 감정을 골랐을 때, 그 다음에 올 단어를 예측하기 위해 **조건부 확률(*P*)**을 계산합니다. 9분할 UI라면 상위 9개의 단어를 뽑아 배치해야 함.

- **1차 추천 (S 추천)**: 감정(*E*)이 선택되었을 때 주어(*S*)가 나타날 확률
    
    *P*(*S*∣*E*)=*Count*(*E*)*Count*(*E*,*S*)
    
- **2차 추천 (O 추천)**: 감정(*E*)과 주어(*S*)가 선택되었을 때 목적어(*O*)가 나타날 확률
    
    *P*(*O*∣*E*,*S*)=*Count*(*E*,*S*)*Count*(*E*,*S*,*O*)
    
- **3차 추천 (V 추천)**: 앞선 맥락(*E*,*S*,*O*)이 모두 선택되었을 때 서술어(*V*)가 나타날 확률
    
    *P*(*V*∣*E*,*S*,*O*)=*Count*(*E*,*S*,*O*)*Count*(*E*,*S*,*O*,*V*)
    

> **Tip**: 데이터가 부족해 확률이 0이 되는 경우를 대비해 **Back-off** 알고리즘(데이터가 없으면 한 단계 상위 조건으로 이동)을 적용하면 더 유연한 추천이 가능함.
> 

### **3단계: 표층형 생성 (Surface Form Generation)**

전처리 단계에서 원형(`좋다`, `먹다`)으로 저장했던 단어들을 환자가 바로 사용할 수 있는 **구어체 종결 어미**로 변환하는 과정입니다. 고령 사용자를 고려해 정중하거나 친근한 말투로 변형.

| 원형 (Lemma) | 변환 후 (UI 노출용) | 비고 |
| --- | --- | --- |
| **좋다** | 좋아요 / 좋구나 | 감정에 따른 종결 |
| **먹다** | 먹고 싶어 / 먹었어 | 시제 및 의도 반영 |
| **보고 싶다** | 보고 싶다 / 보고 싶네 | 친근한 표현 |
- 이 과정에서 **'문장 완성' 버튼**을 별도로 두지 않고, 서술어 선택 시 바로 문장이 발화되도록 설계하면 시선 이동을 1회 더 줄일 수 있음.

### **4단계: 9~12분할 UI 매핑 및 최적화**

아이트래킹의 정밀도 문제를 해결하기 위해 AI가 계산한 확률 결과를 화면에 배치하는 전략.

1. **Fitts's Law 배치**: 확률이 가장 높은 단어(Top 1)를 화면의 **중앙**이나 **시선 이동 경로의 최단 거리**에 배치합니다.
2. **동적 리스트 업데이트**: 사용자가 [기쁨]을 응시하는 순간, 주변 8개 칸이 즉시 [주어(S)] 후보들로 바뀝니다.
3. **예외 처리 (기타/직접 입력)**: 추천 리스트에 원하는 단어가 없을 경우를 대비해 항상 1개 칸은 **'직접 입력'** 혹은 **'다음 페이지'** 기능을 할당합니다.

### **요약하자면:**

1. **데이터셋**에서 형태소 분석기로 S-O-V를 뽑아내고,
2. 이들을 **트리 구조**나 **확률 테이블**로 연결한 뒤,
3. 사용자가 한 칸을 고를 때마다 **다음 노드의 확률 상위 9개**를 화면에 뿌려주는 방식
4. 마지막엔 **어미 처리**를 통해 자연스러운 문장으로 완성

  - 프론트엔드에서 미리 와이어프레임 구성할 생각 못한 점
- **Try**
  - 구체적으로 구현할 기능들에 대해 모두가 뇌 공유를 한 뒤 문서 작업을 할 수 있도록 와이어프레임 만들어야 함
