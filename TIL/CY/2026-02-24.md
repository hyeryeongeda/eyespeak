### 🧠 MLOps
* ML + DevOps 합성어.
* 머신러닝 모델을 개발 -> 배포 -> 운영 -> 모니터링하는 전체 생명주기를 효율적으로 관리하는 방법론

#### 1. MLOps의 3단계 성숙도

- Lv.0 | 수동 프로세스, 스크립트 기반
- Lv.1 | ML 파이프라인 자동화
- Lv.2 | CI/CD 파이프라인 자동화(완전 자동화)

#### 2. MLOps 핵심 구성 요소

- 데이터 관리 : 데이터 수집, 검증, 버전 관리 (DVC, Delta Lake)
- 실험 관리 : 하이퍼파라미터, 메트릭 추적(MLflow, W&B)
- 모델 학습 : 자동화된 학습 파이프라인
- 모델 배포 : 서빙, A/B 테스트, 롤백
- 모니터링 : 데이터 드래프트, 모델 성능 감지

### 다중 파이프라인 (Multi-Pipeline)

- **개념**
  - 하나의 ML 시스템을 여러 파이프라인으로 분리하여 독립적으로 실행·관리하는 구조

```
[데이터 파이프라인]  →  [학습 파이프라인]  →  [배포 파이프라인]
  수집/전처리/검증       모델 학습/평가        서빙/모니터링
```

- **다중 파이프라인이 필요한 이유**
  - 각 단계를 독립적으로 재실행 가능(데이터만 바꿔도 학습 재시작)
  - 팀 간 병렬 작업 가능
  - 장애 발생 시 특정 파이프라인만 재시작 가능
  - 스케줄링 유연성(데이터는 매일, 학습은 주 1회)
- **다중 파이프라인 구성 예시**

```
Pipeline 1 : Feature Engineering  (매일 실행)
Pipeline 2 : Model Training        (주 1회 실행)
Pipeline 3 : Model Evaluation      (학습 완료 시 트리거)
Pipeline 4 : Model Deployment      (평가 통과 시 트리거)
Pipeline 5 : Monitoring            (배포 후 상시 실행)
```

#### 주요 도구 스택

- 파이프라인 오케스트레이션 > Airflow, Kubeflow, Prefect, ZenML
- 실험 추적 > MLflow, Weights & Biasess
- 데이터 버전 관리 > DVC
- 모델 서빙 > BentoML, Seldon, TorchServe
- 컨테이너화 > Docker, Kubernetes
- Feature Store > Feast, Tecton
