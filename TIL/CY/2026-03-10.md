## 자료조사

### 1. UI 메인 컬러 구성 이유
일반적으로 우리가 "눈이 편안한 색"이라고 하면 초록색이나 노란색(미색)을 떠올림.
하지만 **빛의 물리적 성질(파장)**과 **시각적 인지** 측면에서 보면 차이가 있음.

노란색 = 중파장

**단파장(Short-wavelength)** 계열의 배경색이 장파장(빨간색 계열)보다 가독성이 높고 눈의 피로도를 줄이는 데 효과적 (가독성, 눈의 피로함에 대한 웹 사이트 배경색의 영향 논문 참고)

여기서 파장별 색상 구분에 대해 간단히 알아보면:
- **🌈 파장별 색상 구분 (가시광선 스펙트럼)**
    
    빛은 파장의 길이에 따라 에너지가 달라짐.
    
    - **단파장 (Short-wavelength)**
        - 약 **400~500nm**. 보라색, 파란색 계열.
        - 에너지가 강하지만, 논문에서는 ***적절한 대비를 가질 때 가독성이 높고 피로도가 낮다고 분석***했음.
    - **중파장 (Medium-wavelength)**
        - 약 **500~600nm**. 초록색, 노란색 계열
        - 인간의 눈이 가장 민감하게 반응하는 영역
    - **장파장 (Long-wavelength)**
        - 약 **600~700nm**. 주황색, 빨간색 계열
        - 눈의 초점을 맞추기 위해 수정체 근육을 많이 쓰게 하여 피로도가 가장 높음

여기서 질문이 있을 수 있음. **왜 우리는 '노란색/초록색'이 편하다고 느낄까?**

흔히 책의 종이색(미색)이나 숲의 초록색이 편하다고 하는 이유는 **'자극의 정도'** 때문

**초록색 (중파장)**

- 망막에서 색을 감지하는 세포(원추세포)가 가장 편안하게 받아들이는 중간 지점
- 시각적 스트레스가 가장 적은 색으로 알려져 있음

**노란색/미색**

- 순백색의 강한 반사율을 낮춰주기 때문에 '눈부심'을 줄여줌
- 블루라이트 차단 필터가 노란색을 띠는 이유도 에너지가 강한 단파장인 블루라이트를 억제하기 위해서

**논문의 요점 =** 단파장(연한 푸른색) 배경은 시각적으로 **차분하게 가라앉는 느낌(후퇴색)**을 주어, 글자(전진색)를 띄워주고 시선 집중을 돕기 때문에 장시간 응시 시 피로도가 덜하다고 분석한 것

루게릭병 환우분들이 사용하는 **아이트래킹(Eye-tracking)** 환경에서는 단순히 '색이 부드러운가'보다 
**시선을 얼마나 안정적으로 고정할 수 있는가**가 중요

⇒ 그래서 적절한 대비를 활용하여 단파장의 색 조합으로 구성해야 함

## 데일리 회고(KPT)
- **Keep**
  - **사용자 중심 UI/UX 관점으로 사고하려고 한 점**
    - 환자 모드(3×2 최대 6분할 화면)를 설계하면서 단순한 UI가 아니라 루게릭 환자와 고령 사용자에게 얼마나 쉽게 사용할 수 있는지를 중심으로 고민함.
    - 기존 프로젝트에서의 “보기 좋은 UI” 중심 사고에서 벗어나 접근성과 사용성 중심의 UI 설계 관점을 가지게 됨.
  - **사용자 특성을 고려한 컬러 선택**
    - 단파장 계열 색상이 장시간 시청 시 눈의 피로가 적다는 연구를 참고하여 컬러 팔레트 설계 시 반영함.
    - 대비가 과도한 디자인이 아니라 자극을 줄이면서도 강조가 가능한 UI를 고려함.
  - **고령 사용자 중심 인터페이스 고려**
    - 보호자 모드도 고령의 배우자 간병인을 대상으로 하기 때문에
    - 모바일 환경에서도 직관적이고 단순한 UI를 지향하며 설계하려고 한 점.
- **Problem**
  - **유저 중심 UI 설계 경험 부족**
    - 지금까지의 프로젝트는 개발자 관점의 UI 고민이 많았고, 신체적 제약이 있는 사용자와 시니어 사용자 중심 설계 경험이 부족하여 어려움을 느낌.
  - **네이밍 체계가 개발자 중심**
    - 현재 기능 및 카테고리 이름이 개발자만 이해할 수 있는 네이밍으로 구성되어 있음.
    - 실제 서비스 관점에서 보면 직관성이 부족하고 스스로도 헷갈리는 상태.
  - **디자인 검증 부족**
    - 컬러 대비나 UI 배치가 실제 사용자에게 얼마나 편한지 검증되지 않은 상태.
    - 디자인 전문성이 부족하여 판단이 어렵다는 점.
  - **기능 명세 작업 늦어짐**
    - 보호자 모드 기능 명세서 작성이 아직 진행되지 않음.
  - **발표 준비 부족**
    - 기획 배경 → 서비스 소개 구간의 스토리라인이 아직 정리되지 않음.
