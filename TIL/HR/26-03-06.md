
# 26-03-06 한 주의 TIL

## 이번 주 돌아보기

이번 주는 웹캠 기반 시선 추적과 입력 방식에 대해 기술적으로도, 서비스적으로도 많이 고민한 시간이었다.
처음에는 단순히 정확도 문제를 해결하고 싶다는 마음으로 시작했지만, 실제로는 모델 선택, 클릭 방식, 캘리브레이션, UI 구조, 사용자 피로도, 사용 환경까지 모두 연결되어 있다는 걸 계속 체감했다.

특히 이번 주에는 **“기술이 동작하는가”를 넘어서 “사용자가 실제로 쓸 수 있는가”**를 기준으로 생각하려고 노력했다.
그 과정에서 막히는 지점도 많았지만, 단순히 답답해하는 데서 멈추지 않고 원인을 이해하려고 했던 점은 의미 있었던 것 같다.

ai공부를 부족하게 했다 팀의 작업이 더딘 것은 내가 똑바로 하지 못한 것이 크다. 제대로 아는 부분만 보자.

## Keep

이번 주에 가장 잘한 점은, 막히는 지점을 그냥 넘기지 않고 끝까지 확인해 보려 했던 태도였다.
처음에는 “왜 정확도가 이렇게 낮지?”, “왜 가까우면 오히려 인식이 안 되지?”, “왜 블링크가 잘 안 잡히지?” 같은 답답함이 컸지만, 그걸 감으로 넘기지 않고 하나씩 이유를 이해하려고 했던 점이 스스로도 괜찮았다고 느꼈다.

또한 MediaPipe, dlib, YOLO 같은 선택지를 두고 무조건 하나를 정답처럼 받아들이지 않고, **우리 프로젝트의 조건에서 무엇이 더 현실적인지** 계속 비교해 본 것도 좋았다.
웹캠 기반이어야 하고, 루게릭 환자처럼 사용 환경이 분명한 상황에서 어떤 기술이 적합한지 고민해 본 과정은 단순한 기술 검토 이상으로 의미가 있었다고 생각한다.
특히 “왜 이 기술을 써야 하는가”를 설명하려고 했던 흐름은 앞으로도 계속 가져가고 싶다.

아이디어를 실제 화면과 동작으로 구체화해 본 점도 만족스러웠다.
4분할, 9분할, dwell, blink, 이모지 기반 입력, 문장 생성 방식까지 계속 붙여보면서, 기능을 많이 넣는 것보다 **실제 사용자가 덜 피로하고 더 주도적으로 사용할 수 있는 구조가 무엇인지**를 고민했다.
이 과정 덕분에 단순히 구현 가능한 기능이 아니라, 사용자 입장에서 쓸 만한 구조를 생각해 볼 수 있었다.

무엇보다 막막한 순간에도 손을 놓지 않고, 테스트하고, 안 되면 다시 구조를 바꾸고, 자료를 찾아보고, 회의 피드백을 반영하려고 했던 반복 자체가 이번 주의 가장 큰 수확이었다.

## Problem

이번 주에 가장 크게 느낀 문제는, **기술 검토와 구현, 서비스 기획이 동시에 얽혀 있어서 에너지가 많이 분산됐다는 점**이다.
처음에는 모델 정확도 문제를 해결하고 싶어서 시작했지만, 하다 보니 UI 방식, 클릭 트리거, 환자 피로도, 캘리브레이션 문제, 마스크 착용 환경, 저조도 대응까지 전부 연결되어 있었다.
하나를 해결하려 하면 다른 문제가 같이 튀어나와서, 분명 열심히 하고 있는데도 진도가 선명하게 나가는 느낌은 덜했다.

또 하나는, **이 작업이 AI 파트에서 얼마나 의미 있게 보일 수 있는가**에 대한 고민이었다.
브라우저에서 바로 동작하는 모델을 사용하면 빠르게 PoC는 만들 수 있지만, 팀 내에서는 “이 정도면 프론트 구현 아닌가?”라는 질문이 나올 수 있고, 나 역시 그 지점이 계속 걸렸다.
반대로 커스터마이징 가능한 모델 쪽으로 가자니 데이터셋, 학습 환경, 정확도 검증까지 한 번에 일이 커지면서 현실적인 일정과 충돌했다.
기술적으로 깊게 가고 싶은 마음과, 프로젝트 일정 안에서 끝낼 수 있어야 한다는 조건 사이에서 계속 줄타기를 했던 한 주였다.

사용자 관점에서도 답답한 지점이 분명했다.
웹캠 기반 시선 추적은 생각보다 사용 환경의 영향을 많이 받았고, 특히 거리, 조명, 얼굴 가림, 블링크 인식률 같은 요소들이 실제 사용성을 크게 흔들었다.
루게릭 환자처럼 정말 섬세한 입력이 필요한 상황에서는, **“작동은 한다”와 “쓸 만하다” 사이의 차이**가 생각보다 훨씬 크다는 걸 많이 느꼈다.

개인적으로는 자료를 많이 보고 시도도 많이 했지만, 머릿속 정리가 그 속도를 따라가지 못한 순간도 있었다.
분명 공부는 하고 있는데, 내가 지금 무엇을 검증했고 무엇을 보류했는지, 다음에는 무엇을 해야 하는지가 흐려질 때가 있었다.
탐색 범위가 넓어지고 있는 만큼, 정리 방식도 더 명확해질 필요가 있다는 걸 느꼈다.

## Try

다음 주에는 제일 먼저, 문제를 한 번에 다 해결하려 하지 않고 **우선순위를 더 명확하게 나누는 것**부터 해보려고 한다.
정확도 개선, 클릭 방식, UI 구조, 환자 사용성을 하나의 큰 문제로만 보지 않고, 이번 주에는 어디까지 검증할 것인지 먼저 정한 뒤 움직여야 할 것 같다.
그래야 덜 흔들리고, 팀원들과도 더 명확하게 공유할 수 있을 것 같다.

기술 선택도 이제는 “좋아 보이는 기술”보다 **이번 프로젝트 안에서 끝까지 가져갈 수 있는 기술인지**를 기준으로 판단하려고 한다.
MediaPipe, dlib, YOLO 기반 커스터마이징 모두 장단점을 어느 정도 살펴본 만큼, 이제는 우리의 사용자 조건과 일정 안에서 무엇을 포기하고 무엇을 가져갈지 더 분명하게 정리할 필요가 있다.
기술적인 멋보다 서비스 완성도를 우선하는 기준을 세우는 것이 중요하다고 느꼈다.

실행 측면에서는, 실험 결과와 느낀 점을 그때그때 짧게라도 기록하는 습관을 더 강화하려고 한다.
예를 들어 “이 거리에서 블링크 인식이 떨어졌다”, “이 UI는 눈 피로가 크다”, “이 방식은 환자 입장에서 복잡하다” 같은 식으로 바로 남기면, 나중에 같은 고민을 반복하지 않아도 되고 팀과 공유할 때도 훨씬 설득력이 생길 것 같다.
이번 주에 느낀 막막함 중 일부는 기록이 부족해서 생긴 부분도 있었다고 생각한다.

또한 사용자 중심 관점도 더 구체적으로 가져가 보려고 한다.
단순히 “기술적으로 가능한가?”에서 멈추지 않고, “정말 이 사용자가 오래 쓸 수 있을까?”, “실수했을 때 되돌리기 쉬운가?”, “피로를 줄일 수 있는가?”를 계속 기준으로 삼아 화면과 동작을 정리해 보고 싶다.
이번 주에 고민했던 이모지 입력, 4분할/9분할, dwell과 blink 조합도 다음 주에는 더 일관된 기준으로 묶어볼 생각이다.

마지막으로, 다음 주에는 스스로에게도 조금 더 여유를 가지려고 한다.
이번 주는 답이 빨리 보이지 않아 조급했던 순간도 있었지만, 돌이켜보면 그냥 헛돌기만 한 것은 아니었다.
문제를 더 정확히 이해하게 되었고, 무엇이 현실적으로 어려운지도 분명히 알게 되었다.
다음 주에는 이걸 바탕으로 작고 확실한 검증을 하나씩 쌓아가면서, **“많이 고민한 주”에서 “조금 더 정리되고 앞으로 나아간 주”**로 만들어 보고 싶다.
