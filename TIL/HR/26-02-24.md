## 후보 A — “AI 실기 코치(조리자격증 실기)”

### 1) 아이디어 개요
- **한 줄 요약**  
  조리자격증(특히 실기) 준비생이 집에서도 제대로 연습할 수 있도록, 조리 과정을 촬영하면 **위생·안전·조리 순서의 감점 위험 행동을 실시간 탐지**하고 종료 후 **타임스탬프 리포트로 개선 포인트**를 주는 “AI 실기 코치” 서비스.

- **타겟**
  - 조리기능사/조리산업기사 등 **실기 시험** 준비생
  - 학원 외 시간에 독학/반복 연습이 필요하지만 **피드백 코치가 없는** 사용자

### 2) 제공 가치 / 주요 기능
- **실시간 감점 위험 알림(오버레이/알림음)**
  - 위생복·위생모 착용 누락, 손 위생 미수행
  - 교차오염 가능 행동(도마/칼 세척 누락 후 재료 변경)
  - 화상/칼 안전 위험, 정리정돈 미흡 신호 등
- **메뉴/과제별 단계 체크(타이머 + 체크리스트)**
  - “준비→손질→가열→플레이팅→정리” 단계 진행률 표시
- **사후 리포트(타임라인)**
  - 예: `00:32 도마 미세척 후 재료 전환(감점 위험)`처럼 **언제/무엇/왜**를 명확히
- **약점 반복 학습(미션 재연습)**
  - 약점 TOP3 자동 생성 → 해당 구간만 재촬영/훈련
- **MVP 범위(현실화)**
  - 전 종목 커버 X  
  - **공통 감점(위생·안전·정리정돈) + 메뉴 1~2개**로 시작

### 3) User Flow
1. 종목/메뉴 선택  
2. 촬영 세팅 안내(각도/거리/조명)  
3. 조리 시작(실시간 경고/체크리스트)  
4. 종료(점수 추정/타임라인 리포트)  
5. 약점 미션 재연습 + 변화 추적

### 4) Why AI Video?
- 실기 시험은 완성 결과물이 아니라 **‘과정(위생·안전·순서·정리정돈)’**에서 감점이 크다.
- 집 연습에서 사용자가 **감점 행동을 스스로 인지하기 어렵고**, 이건 영상에서만 잡히는 행동/상태 신호로 해결 가능.
- 채점 기준 근거(규칙 정의 근거)가 있어 **‘설명 가능한 피드백’**을 설계하기 좋다.  
  - 참고: Q-Net 공개 자료(위생/안전 채점 기준 등)

### 5) 기술 포인트(차별점)
- **감점 규칙 엔진(Scoring/Rule Engine)**  
  - `영상 이벤트(행동/상태) → 감점 항목 매핑 → 근거/개선 미션`으로 변환
- **객체 탐지 + 손/포즈 + 행동 인식(Temporal) 결합**
  - “무엇이 보였나”에서 끝나지 않고 “무엇을 했나”로 확장
- **확장형 구조**
  - 공통 감점 모듈 + 메뉴별 플러그인 구조
- **프라이버시 친화**
  - 원본 영상 저장 최소화(이벤트 로그/점수/짧은 클립만 선택 저장)

### 6) 구현 후보 기술 스택(초안)
- Object Detection: YOLO 계열(위생모/앞치마, 칼/도마, 재료, 불/가열 등)
- Hand/Pose: MediaPipe Hands/Pose(접촉 대상 추적)
- Action Recognition: SlowFast / TimeSformer / Video Swin 등(동작의 시간축 인식)
- Rule Engine: 이벤트 기반 스코어링 + 근거 텍스트 생성

### 7) 데이터 수집/전처리 계획(초안)
- **1차(팀 자체 수집)**: 거치대 고정, 상판/손/도구가 보이는 각도 표준화, 메뉴 1~2개 집중
- **2차(공개 데이터 부트스트랩)**: EPIC-KITCHENS 등 주방 행동/객체 라벨 데이터 참고
- 라벨링 전략: “메뉴 전체”가 아니라 **감점 이벤트 중심**
  - 위생: 손씻기 미수행, 얼굴/머리 만짐
  - 교차오염: 도마/칼 세척 누락 후 재료 전환
  - 안전: 칼 방치, 화상 위험 동작
- 전처리: 2~5초 클립 추출 → 이벤트 구간 라벨링 → 조명/가림/흔들림 증강
- Active Learning: 헷갈리는 구간 우선 라벨링

## 후보 B — “청각장애 커뮤니케이션(특히 의료/업무/초동민원)”

### 1) 현황 요약
- **STT(실시간 자막)**는 이미 완성도가 높고 실사용이 많음.
- 반면 **실시간 수어 번역(손/표정 포함)**은 정확도·환경 민감도·문법 차이로 신뢰가 낮아 “주력 UX”로 채택이 어렵다.
- 결론: **“말(STT)은 보지만, 손(수어 번역)은 아직 안 믿는다”** 쪽에 더 가깝다.

### 2) 기존 앱/기능(요약)
- STT: 구글 음성 자막 변환, Ava, 소보로 등
- 소리 인식/알림: iOS/안드로이드 소리 인식 기능, SeeSound 등
- 중계: 손말이음센터(124) 등 “사람이 개입하는” 방식은 신뢰도가 높음

### 3) 기존 솔루션의 체감 한계(차별화 포인트)
- 전문용어 오인식/오번역(특히 의료/법률)
- 다중 대화/소음 환경에서 자막 품질 급락
- 딜레이로 대화 흐름이 끊김
- (수어 번역의 경우) 손만 인식 → 표정/입모양(NMM) 미반영, 어순/조사 차이, 조명/배경 민감

### 4) 노릴 수 있는 “돈 되는” 니치(초안)
- **의료(개인병원/약국)**
  - 반복 패턴(문진/복약지도) + “기록/요약” 가치가 큼  
  - 단, 오인식 시 리스크 → **최종 확인 UX/안전장치** 필수
- **직장(B2B: 직무교육/회의)**
  - 전용 용어 사전 + 회의록 자동 생성(보안 요구: 온디바이스 선호)
- **초동 민원/사법 초기 대응**
  - 통역사 도착 전 ‘골든타임’ 기록(진술 초안) 가치  
  - 데이터 무결성/위변조 방지 등 법적 요구가 커 난이도 상승

### 5) 비교 테이블(초안)
| 구분 | 시장/빈도 | 기술 난이도 | 기록 모드 가치 | 추천 |
|---|---:|---:|---:|---:|
| 의료(개인병원) | 상 | 중 | 최상 | ⭐⭐⭐⭐⭐ |

## 결합 아이디어(가능성 메모)
- “조리 실기 코치”와 “접근성(STT/기록)”은 **직접 결합보다는**  
  공통 구조(실시간 안내 + 타임라인 리포트 + 개인화 약점/기록)를 공유하는 방식이 더 자연스러움.
- 즉, **“실시간 코칭 + 종료 후 리포트(타임스탬프)”**를 제품 패턴으로 정립하고  
  도메인만 조리/의료/업무로 바꾸는 전략이 가능.
