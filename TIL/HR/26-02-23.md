# 📌 오늘 공부한 내용 (TypeScript)

## 1) 타입 가드 / narrowing

**목표:** API에서 `unknown`으로 들어온 응답을 “안전하게” 원하는 타입으로 좁혀서 사용하기

### 핵심 포인트

* `unknown`은 **바로 접근 불가** → 런타임에서 최소한의 형태 검증 필요
* `typeof`, `in`, `Array.isArray()` + 커스텀 타입가드로 narrowing

### 예시 패턴

```ts
type JsonObject = Record<string, unknown>;

function isObject(v: unknown): v is JsonObject {
  return typeof v === "object" && v !== null;
}

function hasKey<K extends string>(
  obj: JsonObject,
  key: K
): obj is JsonObject & Record<K, unknown> {
  return key in obj;
}

// 사용 예: unknown 응답 파싱
function parseTitle(res: unknown): string {
  if (!isObject(res)) throw new Error("response is not object");
  if (!hasKey(res, "title") || typeof res.title !== "string") {
    throw new Error("invalid title");
  }
  return res.title; // 여기서부터 res.title은 string으로 좁혀짐
}
```

### 체크포인트

* `as` 캐스팅은 마지막 수단 (검증 없이 쓰면 런타임 터짐)
* “필요 최소 필드만” 확인해도 안정성 크게 올라감

## 2) 유니온 / 제네릭으로 API 응답을 `ApiEnvelope<T>`로 일반화

**목표:** API 응답 구조가 항상 `{ success, data, message }` 같은 형태라면, 이를 제네릭으로 통일해서 **화면 코드 단순화**

### 예시 타입

```ts
export type ApiEnvelope<T> = {
  success: boolean;
  data: T;
  message?: string;
  code?: string | number;
};
```

### 활용 예

```ts
type User = { id: string; name: string };

async function fetchUser(): Promise<ApiEnvelope<User>> {
  const res = await fetch("/api/user");
  const json: unknown = await res.json();

  // 여기서 json을 ApiEnvelope<User>로 바로 믿지 말고,
  // (1) 타입가드 or (2) zod로 검증 후 반환하는 게 안정적
  return json as ApiEnvelope<User>;
}
```

### 유니온으로 “성공/실패”를 더 강하게 표현

```ts
type ApiOk<T> = { success: true; data: T; message?: string };
type ApiFail = { success: false; data?: unknown; message: string; code?: string | number };
type ApiResult<T> = ApiOk<T> | ApiFail;

function unwrap<T>(r: ApiResult<T>): T {
  if (!r.success) throw new Error(r.message);
  return r.data;
}
```

**장점:** `if (!success) ...` 체크를 안 하면 컴파일 단계에서 불편해져서 실수 줄어듦.

## 3) 런타임 검증 : Zod로 “타입=데이터” 갭 줄이기

**목표:** TypeScript 타입은 컴파일 때만 존재 → 서버 응답은 런타임 데이터
→ Zod로 “실제 데이터가 타입과 맞는지” 검증하고 안전하게 사용

### 예시

```ts
import { z } from "zod";

const UserSchema = z.object({
  id: z.string(),
  name: z.string(),
});

const EnvelopeSchema = <T extends z.ZodTypeAny>(dataSchema: T) =>
  z.object({
    success: z.boolean(),
    data: dataSchema,
    message: z.string().optional(),
    code: z.union([z.string(), z.number()]).optional(),
  });

type User = z.infer<typeof UserSchema>;

async function fetchUserSafe(): Promise<User> {
  const res = await fetch("/api/user");
  const json = await res.json(); // unknown 대신 any처럼 들어옴

  const parsed = EnvelopeSchema(UserSchema).parse(json); // 여기서 런타임 검증
  if (!parsed.success) throw new Error(parsed.message ?? "request failed");
  return parsed.data;
}
```

### 체크포인트

* `parse()`는 실패 시 예외 throw (빠르게 터뜨려서 원인 추적 쉬움)
* 프로덕션에서는 `safeParse()`로 에러 처리 패턴을 선택할 수도 있음

---

## 요약

* `unknown` 응답을 **타입가드로 narrowing**하고, 응답 래퍼는 **`ApiEnvelope<T>`로 제네릭 통일**, 더 안전하게는 **Zod로 런타임 검증**을 추가하면 프론트의 안정성이 올라간다.
