## 🧠 Learned (배운 것)

* **타겟이 고령 중증환자면, 이모지의 목적은 ‘감성’보다 ‘돌봄/증상 전달’이 우선**일 가능성이 큼.
* **UI 칸 수가 늘어날수록(4 → 9)**

  * 탐색(눈으로 찾기) 시간이 길어지고,
  * 응시/고정 시간이 늘어 **눈 피로도가 증가**할 수 있음.
* MediaPipe 같은 기존 기술을 쓰더라도, 제품 가치는

  * **환자 환경(피로/조명/각도/인지 편차)**에서 **지속 가능하게 동작하는 UX 설계**에서 갈릴 수 있음.

## 🔧 Next (내일 할 일 / 팀회의 산출물)

### 1) 타겟 확정 반영

* MVP 주 사용자: **고령 중증환자**(시선/눈 제스처가 주요 입력 채널)
* UI/카피/이모지 구성 우선순위: **돌봄 · 증상 · 긴급** 중심으로 고정

### 2) 이모지 카테고리 와이어프레임 초안

* 음식 중심 제외, **5탭 구조**로 초안 제작

  * 🚨 긴급 / 🤕 증상 / 🛏️ 돌봄 요청 / 😊😣 상태·감정 / 📞 호출·연락
* 원칙: **이모지 단독 금지 → “이모지 + 라벨”** (예: `🤕 아파요`)

### 3) 4칸 vs 9칸 와이어프레임 비교안 제작 (MediaPipe 입력 전제)

* “시연 시나리오”가 아니라, **화면 설계 비교 산출물**로 준비
* 동일한 기능에서 **그리드만 2안**

  * A안: **2×2(4칸)** — 초단순, 탐색 부담↓
  * B안: **3×3(9칸)** — 표현력↑, 탐색/피로 부담↑
* 와이어프레임 주석으로 비교 포인트 명시

  * 선택 대상 탐색 난이도(시선 이동량)
  * 오선택 가능성(칸 밀도)
  * dwell/블링크 트리거 시 **실수 복구 동선**(되돌리기/취소)

### 4) 와이어프레임 산출물 정의(회의 결과물)

* 최소 구성(내일 범위)

  * 홈/모드 선택(큰 버튼)
  * 카테고리 탭(5개)
  * 보드 화면(4칸/9칸 2안)
  * 선택 결과 프리뷰(라벨 크게 표시) + 실행(전송/읽기)
  * 오작동 방지 UI(게이지/쿨다운/취소)
