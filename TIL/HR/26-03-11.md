# [TIL] 여가 기능 YouTube 연동, 상태 관리, API 역할 분리


## Context (03-11)

오늘은 ALS 의사소통 서비스의 **여가 기능**을 구현하는 흐름을 고민하다가,
`풍경 / 야구 / 뉴스 / 음악` 같은 카테고리에서 **YouTube 콘텐츠를 어떻게 불러오고**,
재생 화면에서 **현재 영상 / 다음 콘텐츠**를 어떤 구조로 처리해야 하는지가 궁금해서 공부를 시작했다.

처음에는 단순히 “유튜브 영상을 화면에 띄우면 되는 거 아닌가?”라고 생각했는데,
정리해보니 이건 단순 영상 삽입 문제가 아니라,

* 외부 콘텐츠를 화면에 임베드하는 방법
* 카테고리별 영상 목록 관리
* 현재 재생 중인 영상 상태 관리
* 다음 콘텐츠 계산
* 프론트와 백엔드의 역할 분리

까지 함께 이해해야 하는 문제였다.

---

## What I Learned

### 1. YouTube 연동은 "영상 재생"과 "목록 관리"를 나눠서 봐야 한다

처음에는 YouTube를 붙인다고 하면 그냥 영상 하나 띄우는 것만 생각했는데,
실제로는 아래 두 가지를 분리해서 이해해야 했다.

#### 1) 영상 재생

왼쪽 큰 영역은 결국 **현재 선택된 `videoId` 하나를 재생하는 영역**이다.
이 부분은 `iframe` embed 방식으로 처리할 수 있다.

```html
<iframe
  width="100%"
  height="100%"
  src="https://www.youtube.com/embed/VIDEO_ID"
  title="YouTube player"
  frameborder="0"
  allowfullscreen
></iframe>
```

즉, 프론트는 재생 자체보다
**"지금 어떤 `videoId`를 재생할 것인가"** 를 관리하는 게 핵심이다.

#### 2) 다음 콘텐츠

오른쪽 아래의 “다음 콘텐츠”는 YouTube 플레이어가 자동으로 제공하는 개념이 아니라,
**현재 카테고리의 영상 목록 중 다음 순번을 프론트가 계산해서 보여주는 구조**였다.

즉 이 기능은 사실상:

* 현재 카테고리의 영상 목록
* 현재 재생 중인 index
* 다음 영상 정보

를 기반으로 동작한다.

---

### 2. 이 기능의 핵심은 유튜브가 아니라 React 상태 관리다

오늘 가장 크게 이해한 점은
이 기능이 "유튜브 공부"보다 **상태 관리(state)** 가 더 중요하다는 것이다.

재생 화면에서는 최소한 아래 상태가 필요하다.

```tsx
const [category, setCategory] = useState("baseball");
const [videos, setVideos] = useState<VideoItem[]>([]);
const [currentIndex, setCurrentIndex] = useState(0);
```

이 상태들을 기준으로 보면:

* `category`: 현재 선택한 카테고리
* `videos`: 현재 카테고리의 영상 목록
* `currentIndex`: 현재 재생 중인 영상 위치

가 된다.

그리고 실제 화면 데이터는 이렇게 계산된다.

```tsx
const currentVideo = videos[currentIndex];
const nextVideo = videos[currentIndex + 1];
```

즉, “다음 콘텐츠”는 별도 복잡한 기능이 아니라
**배열에서 다음 항목을 꺼내 보여주는 구조**라는 걸 이해했다.

---

### 3. "다음 콘텐츠"는 추천 시스템이라기보다 우선은 index 이동이다

처음에는 “연관 콘텐츠”를 유튜브가 자동으로 추천해주는 줄 알았는데,
실제로 프론트 입장에서는 우선 그렇게 접근하면 안 되고,
MVP 기준으로는 아래처럼 생각하는 게 더 맞았다.

* 카테고리별 영상 목록을 준비한다
* 첫 번째 영상을 재생한다
* 사용자가 “다음 콘텐츠”를 누르면 `currentIndex + 1`
* 다음 영상으로 교체한다

예를 들면:

```tsx
const handleNext = () => {
  if (currentIndex < videos.length - 1) {
    setCurrentIndex((prev) => prev + 1);
  }
};
```

즉, 지금 단계에서 “다음 콘텐츠”는
**추천 알고리즘**보다 **현재 목록 내 다음 영상 이동 기능**으로 설계하는 게 맞다.

---

### 4. 프론트와 백엔드의 역할을 구분해서 생각해야 한다

오늘 가장 헷갈렸던 부분 중 하나가
“프론트가 유튜브를 직접 불러오는지, 백엔드가 처리하는지”였다.

정리하면 다음과 같다.

#### 프론트 역할

* 카테고리 선택 UI
* 현재 영상 재생 UI
* 다음 콘텐츠 카드 표시
* 현재 영상 상태 관리
* 다음 콘텐츠 클릭 시 index 변경

#### 백엔드 역할

* 카테고리별 YouTube 영상 목록 관리
* YouTube API 호출
* 영상 데이터 정리
* 프론트가 쓰기 쉬운 형태로 응답 가공

즉, 프론트는 **받아온 데이터를 화면에 연결하는 역할**,
백엔드는 **유튜브 데이터를 가져오고 정리하는 역할**이다.

이 구분을 이해하니까,
프론트에서 어디까지 공부해야 하는지도 훨씬 명확해졌다.

---

### 5. 처음부터 YouTube API를 붙이기보다 mock 데이터로 먼저 구조를 잡아보아야겠다.

이 부분도 중요한 포인트였다.
처음부터 외부 API를 붙이면 복잡도가 너무 올라가서,
먼저 더미 데이터로 흐름을 구현하는 게 당황하지 않고 오류 작업을 할 수 있을 것 같다.

예를 들면:

```tsx
const mockVideos = {
  baseball: [
    { videoId: "aaa111", title: "야구 하이라이트 1" },
    { videoId: "bbb222", title: "야구 하이라이트 2" },
  ],
  music: [
    { videoId: "ccc333", title: "추억의 가요 1" },
    { videoId: "ddd444", title: "추억의 가요 2" },
  ],
};
```

이런 식으로 먼저:

* 카테고리 선택
* 목록 교체
* 첫 영상 재생
* 다음 콘텐츠 표시
* 다음 콘텐츠 클릭 시 현재 영상 변경

까지 완성한 뒤,
나중에 실제 API 응답 구조로 바꾸는 방식이 더 낫다.

---

### 6. 내가 공부해야 할 건 "유튜브"보다 "외부 데이터를 React 화면에 연결하는 방법"이다

오늘 대화를 통해 정리된 핵심은 이거였다.

내가 지금 공부해야 하는 것은:

1. `iframe`으로 외부 영상을 임베드하는 방식
2. React `useState`, `useEffect`
3. `fetch` / `axios`를 이용한 API 호출
4. 배열/객체 기반 데이터 구조 설계
5. 컴포넌트 분리
6. 프론트/백엔드 역할 분리

즉, 본질은 유튜브 자체보다
**외부 데이터를 받아와서 현재 상태에 맞게 UI로 연결하는 흐름**이었다.

---

**여가 기능의 YouTube 연동은 단순 영상 삽입이 아니라, 카테고리별 외부 영상 데이터를 React 상태 흐름으로 연결하는 문제**였다.
