# 2026-02-26  TIL — 웹캠 기반 시선(eye gaze) AAC PoC 개선: 3×3 그리드 + 더블블링크 캘리브레이션

## 오늘 한 일 (What I did)

* **MediaPipe FaceMesh(refineLandmarks=iris)** 기반으로 웹캠에서 **홍채/눈뜸/얼굴 특징(feature)** 추출
* **9점(3×3) 캘리브레이션 → centroid(중앙값) 학습 → 최근접 분류**로 시선 영역 결정
* UX 요구사항 반영

  * 페이지 진입 시 **안내 문구 먼저 노출**
  * **Start 버튼으로 카메라 ON** (자동 시작 X)
  * **더블 블링크**로 **캘리브레이션 시작/다음 점 스킵**
  * 캘리브레이션 후 **확대 선택창 제거**, **화면 3×3(9칸)에 단어를 직접 배치**하고 응시로 즉시 실행

## 구현 로직 요약 (How it works)

### 1) Feature 추출

* FaceMesh 랜드마크에서:

  * **iris 중심 좌표를 eye-box로 정규화**(좌/우 눈 각각)
  * **eye openness(눈뜸 비율)**로 깜빡임 신호 확보
  * 얼굴 bounding 기반 **face center/size + 양눈 거리** 등 보조 특징 추가
    → 최종 feature 벡터로 현재 시선 상태를 표현

### 2) 캘리브레이션(9점) & 모델(centroid) 학습

* 3×3 각 칸 중심을 순회하며 **0.2s 안정화 + 0.8s 샘플 수집(총 1.0s/점)**
* 수집 샘플에서 **median centroid** 계산(평균보다 튐/노이즈에 강함)
* 결과: `centroids[9]`가 “각 칸을 볼 때의 대표 특징값”이 됨

### 3) 실행(분류 + Dwell 선택)

* 매 프레임 현재 feature를 계산하고,
* **nearest centroid(유클리드 거리 최소)** 칸을 hot cell로 지정
* hot cell이 **일정 시간(dwellMs)** 유지되면 해당 칸의 액션 실행

  * 문구 append / 1줄 삭제 / 전체 삭제 등

## 더블 블링크(캘리브레이션 제어) 설계

* eye openness의 baseline을 2~3초 동안 완만하게 업데이트
* openness가 baseline 대비 특정 비율 이하로 떨어졌다가 복귀하면 blink로 판정
* **0.8초 이내 2회 blink = double blink**

  * 캘리브레이션 시작 트리거
  * 캘리브레이션 중 **다음 점 즉시 이동(스킵)**

## 문제/이슈 & 해결 (Problems & Fixes)

* **웹캠 기반 시선은 가장자리/상하단 정확도가 약함**

  * 해결: 시스템 커서 제어 대신 **영역(3×3) 분류**로 목표를 “거칠게” 만들고
  * UI를 중앙에 두어 사용 가능 범위를 안정화
* **캘리브레이션 시간이 길면 사용자 피로가 큼**

  * 해결: 점당 1.0초로 단축 + **더블 블링크 스킵** 제공
* **초기 진입 시 자동으로 카메라가 켜지는 UX 부담**

  * 해결: 안내 먼저 → **Start 버튼**으로 사용자가 통제

## 거리/세팅 가이드 (Accuracy Tips)

* 권장: **얼굴이 화면에서 너무 작지 않게**(대략 세로 기준 화면 높이의 35~55% 정도 차지)
* 카메라-얼굴 거리 감각:

  * 일반 웹캠이면 보통 **40~70cm**가 안정적인 편
  * 너무 멀면 홍채 픽셀 수가 줄어 노이즈 증가, 너무 가까우면 시야가 잘리고 왜곡 증가
* 조명은 정면/확산광이 유리(역광이면 landmark 튐)

## 회고 (Learnings)

* “정밀 좌표 회귀(커서)”보다 **영역 분류(3×3) + dwell**이 웹캠 환경에서 훨씬 강건함
* 캘리브레이션 UX를 **블링크 제스처**로 통제하면 입력 장치가 없는 사용자에게도 자연스러움
* PoC 단계에서 가장 중요한 건 정확도 자체보다 **피로도(시간/인지부하) 낮추는 인터랙션 설계**
