## 1. 데이터베이스와 DBMS의 이해

### 개념

- **데이터 vs 정보**: 가공되지 않은 사실(데이터)을 목적에 맞게 처리하면 가치 있는 '정보'가 됨.
- **DBMS (Database Management System)**: 데이터를 효율적으로 관리, 저장, 조회하기 위한 소프트웨어. (예: MySQL, Oracle, PostgreSQL)
- **RDBMS (관계형 DB)**: 데이터를 테이블(행과 열) 구조로 관리하며, SQL을 표준 언어로 사용함.

---

## 2. SQL의 종류와 역할

SQL은 목적에 따라 크게 4가지로 분류됩니다.

| 분류 | 이름 | 역할 | 주요 명령어 |
|---|---|---|---|
| DDL | 데이터 정의어 | 데이터 구조 정의 | `CREATE`, `ALTER`, `DROP`, `TRUNCATE` |
| DML | 데이터 조작어 | 데이터 관리 | `INSERT`, `SELECT`, `UPDATE`, `DELETE` |
| DCL | 데이터 제어어 | 권한 제어 | `GRANT`, `REVOKE` |
| TCL | 트랜잭션 제어 | 작업 일관성 유지 | `COMMIT`, `ROLLBACK` |

---

## 3. 데이터 설계의 핵심: 제약 조건

데이터의 **무결성(정확성)** 을 지키기 위해 설정합니다.

| 제약 조건 | 설명 |
|---|---|
| `PRIMARY KEY` (기본 키) | 행을 식별하는 유일한 값 (중복 X, NULL X) |
| `FOREIGN KEY` (외래 키) | 다른 테이블과의 관계를 연결 |
| `NOT NULL` | 필수 입력 항목 |
| `UNIQUE` | 중복 값 허용 안 함 |
| `DEFAULT` | 값이 없을 때 기본값 자동 입력 |
| `CHECK` | 특정 조건 만족 여부 검사 |

## 4. 데이터 조회와 가공 (SELECT)

### 기본 검색
`WHERE` 절을 사용하여 특정 조건을 필터링합니다.
```sql
SELECT * FROM products WHERE price BETWEEN 1000 AND 5000;
SELECT * FROM members WHERE name LIKE '김%'; -- '김'으로 시작하는 모든 이름
SELECT * FROM orders WHERE status IN ('PENDING', 'SHIPPED');
```

### 정렬과 제한
```sql
SELECT * FROM products ORDER BY price DESC LIMIT 10;
-- ORDER BY: ASC(오름차순) / DESC(내림차순)
-- LIMIT: 출력 개수 제한
```

### 함수 활용

- **문자열**: `CONCAT` (합치기), `SUBSTRING` (자르기)
- **NULL 처리**: `IFNULL`, `COALESCE`
- **조건문**: `CASE WHEN ... THEN ... ELSE ... END`

```sql
SELECT CONCAT(first_name, ' ', last_name) AS full_name FROM users;
SELECT IFNULL(phone, '번호 없음') FROM members;
SELECT name,
       CASE WHEN score >= 90 THEN 'A'
            WHEN score >= 80 THEN 'B'
            ELSE 'C'
       END AS grade
FROM students;
```

## 5. 집계와 그룹핑 (통계 산출)

### 집계 함수
`COUNT` (개수), `SUM` (합계), `AVG` (평균), `MAX` / `MIN` (최대/최소)

### GROUP BY & HAVING
```sql
-- 카테고리별 평균 가격 조회 (평균이 5000 이상인 그룹만)
SELECT category, AVG(price) AS avg_price
FROM products
GROUP BY category
HAVING AVG(price) >= 5000;
```

> **⚠️ 주의**: `WHERE`는 그룹화 **전** 필터링, `HAVING`은 그룹화 **후** 필터링.

---

## 6. SQL 실행 순서 (매우 중요!)

SQL 쿼리는 **작성 순서**와 **실제 실행 순서**가 다릅니다. 이 흐름을 이해해야 복잡한 쿼리 작성이 가능합니다.

```
① FROM      → 대상 테이블 확인
② WHERE     → 행 필터링
③ GROUP BY  → 데이터 그룹화
④ HAVING    → 그룹 필터링
⑤ SELECT    → 조회할 컬럼 및 계산 수행
⑥ ORDER BY  → 결과 정렬
⑦ LIMIT     → 최종 출력 개수 제한
```

## 💡 오늘의 핵심 포인트

- `UPDATE`나 `DELETE`를 사용할 때는 반드시 **`WHERE` 절을 확인**하여 원치 않는 데이터가 삭제/수정되지 않도록 주의하자.
- **`AUTO_INCREMENT`** 를 활용하면 기본 키 값을 직접 입력하지 않아도 자동으로 1씩 증가하며 저장되어 편리하다.
- 문자열 검색 시 **`%` 와일드카드**를 사용하는 `LIKE` 연산자는 매우 유용하다. (예: `LIKE '김%'` → '김'으로 시작하는 모든 이름)
