### ❌ Problem — 문제가 된 것

#### 1. 준비 없는 회의
오늘 팀 회의는 **충분한 준비 없이 진행**되었고, 결과적으로 모두를 피곤하게 만들었다.

준비가 부족한 회의는 단순히 시간 낭비에 그치지 않는다. 방향성이 불명확한 채로 이어지는 토의는 구성원들의 **인지적 피로도**를 높이고, 결론 없이 끝날 경우 팀 전체의 **사기와 신뢰를 갉아먹는다**. 팀 협력에서 가장 먼저 차단해야 할 비효율 중 하나라고 생각한다.

특히, 우리처럼 **수평적 관계로 운영되는 팀**에서는 권위에 의한 빠른 의사결정이 불가능하다. 모든 구성원이 각자의 아이디어와 논리를 충분히 다듬어 와야만 실질적인 '수평적 논의'가 가능해진다. 준비 없는 참여는, 수평적 팀에서 의사결정을 가장 지지부진하게 만드는 원인이다.

#### 2. AI 영상 생성 모델 직접 구현에 대한 오판
초기에 외부 영상 생성 API(Runway, Pika 등)에 의존하지 않고, **우리가 직접 영상 생성 모델을 만들 수 있을 것이라고 판단했다.** 이는 현실적으로 매우 어렵다는 것을 뒤늦게 깨달았다.

> **기술적 근거:**
> - 현존하는 영상 생성 모델(Sora, Stable Video Diffusion 등)은 수천만 개 이상의 비디오 클립으로 구성된 **TB 단위의 학습 데이터**를 요구한다.
> - 모델 아키텍처 자체가 Diffusion Transformer, 시간축 Attention 등 **최첨단 연구 분야의 복합 기술**로 구성되어 있다.
> - 의미 있는 수준의 영상을 생성하기 위한 학습에는 **수십~수백 장의 고성능 GPU**가 수일~수주간 필요하다.
> - 수십 명의 ML 엔지니어로 구성된 연구팀도 수개월이 걸리는 작업을, 제한된 기간의 프로젝트에서 처음부터 재현하는 것은 사실상 불가능에 가깝다.
>
> 결론적으로, 영상 **생성** 그 자체보다 **탐지 → 분석** 파이프라인을 정교화하는 방향이 훨씬 현실적이고 차별화 가능성이 높다.

#### 3. 컨디션 관리 실패
자바 학습과 주제 선정 등이 겹치며 **피로가 적절히 해소되지 못한 채 팀 활동에 임했고**, 팀원의 의견에 깊이 공감하지 못하는 모습을 보이고 말았다.

> *"Your energy introduces you before you even speak."*
>
> 내 에너지와 태도는 내가 말을 꺼내기도 전에 팀원들에게 먼저 전달된다. 열정적으로 임하는 것과 무리하는 것은 다르다. 팀 전체의 사기를 위해서라도, 나의 컨디션 관리는 개인의 문제가 아니라 **팀에 대한 책임**이다.

## 1. 불변 객체 (Immutable Object)

### 개념
객체가 **생성된 이후 내부 상태(필드)가 절대 변하지 않도록** 설계된 객체.

여러 참조형 변수가 하나의 객체를 공유(공유 참조)할 때, 한 곳에서 값을 변경하면 다른 곳도 영향을 받는 **사이드 이펙트(Side Effect)** 문제가 발생할 수 있다.

이를 방지하기 위해:
- 필드를 `final`로 선언
- 값을 변경하는 `setter` 메서드를 제공하지 않음
- 값 변경이 필요한 경우, **기존 객체를 수정하지 않고 새로운 객체를 생성하여 반환**

### 🏺 비유
> **"한 번 구워진 도자기"** — 찰흙(가변 객체)일 때는 모양을 바꿀 수 있지만, 가마에서 구워진 도자기(불변 객체)는 모양을 바꿀 수 없다. 다른 모양이 필요하면 새 도자기를 새로 만들어야 한다.

### 예시 코드
```java
public class ImmutableObj {

    private final int value; // final로 선언 → 상태 변경 불가

    public ImmutableObj(int value) {
        this.value = value;
    }

    // 기존 객체를 변경하지 않고, 계산 결과로 새 객체를 생성하여 반환
    public ImmutableObj add(int addValue) {
        int result = value + addValue;
        return new ImmutableObj(result);
    }
}
```

### 🌱 실제 Spring에서의 활용
- **Spring Bean**은 싱글톤으로 관리되어 여러 스레드가 동시에 접근하므로, **무상태(Stateless)** 또는 **불변 객체**로 설계해 스레드 안전성(Thread-safety) 확보
- **DTO(Data Transfer Object)** 및 Java 14의 **`record` 타입**은 데이터 오염을 막기 위해 불변으로 설계하는 것이 일반적

## 2. 열거형 (Enum)

### 개념
**미리 정해진 상수 목록만 사용할 수 있도록 강제**하는 타입 안전 열거형 패턴(Type-Safe Enum Pattern)을 Java 언어 차원에서 지원하는 기능.

`String`으로 상태를 관리하면 오타나 유효하지 않은 값이 입력될 수 있지만, `Enum`은 **컴파일 시점에 완벽하게 차단**한다.

### 📝 비유
> **"객관식 답안지"** — 주관식(String)은 아무 단어나 적을 수 있어 오류가 발생하기 쉽지만, 객관식(Enum)은 미리 정해진 보기 중에서만 선택해야 하므로 엉뚱한 값을 원천 차단한다.

### 예시 코드
```java
public enum Grade {
    BASIC(10), GOLD(20), DIAMOND(30); // 정해진 객체만 사용 가능

    private final int discountPercent;

    // Enum의 생성자는 private으로 제한됨
    Grade(int discountPercent) {
        this.discountPercent = discountPercent;
    }

    public int discount(int price) {
        return price * discountPercent / 100;
    }
}
```

### 🌱 실제 Spring에서의 활용
- **Spring Data JPA**에서 DB 컬럼과 매핑할 때 자주 사용
  - 회원 권한: `Role.ADMIN`, `Role.USER`
  - 주문 상태: `OrderStatus.ORDERED`, `OrderStatus.CANCELLED`
- `@Enumerated(EnumType.STRING)` 어노테이션과 함께 사용하여 도메인 비즈니스 로직을 안전하게 보호

## 3. 날짜와 시간 (`java.time` 라이브러리)

### 개념
과거의 `Date`, `Calendar` 클래스는 불변 객체가 아니었고, 윤년·썸머타임·타임존 처리가 매우 불편했다.

**Java 8**부터 이를 완벽히 해결한 `java.time` 패키지가 표준으로 도입되었으며, **모든 클래스가 불변(Immutable)** 으로 설계되었다.

| 클래스 | 설명 |
|---|---|
| `LocalDateTime` | 타임존을 고려하지 않는 날짜/시간 |
| `ZonedDateTime` | 타임존까지 고려하는 날짜/시간 |
| `Period` | 날짜 간격 표현 |
| `Duration` | 시간 간격 표현 |

### 🔪 비유
> **"스위스 아미 나이프(만능칼) 달력"** — 용도에 맞는 도구(`LocalDateTime`, `ZonedDateTime`, `Period` 등)를 꺼내어 오차 없이 정확하게 시간을 계산할 수 있다.

### 예시 코드
```java
// 특정 날짜/시간 생성
LocalDateTime dt = LocalDateTime.of(2018, 1, 1, 13, 30, 59);

// 계산: 불변 객체이므로 반드시 반환값을 받아야 함
LocalDateTime plusDt = dt.plusYears(10);

// 포맷팅 (날짜 → 문자열)
DateTimeFormatter formatter = DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss");
String formattedStr = dt.format(formatter);
```

### 🌱 실제 Spring에서의 활용
- **JPA Auditing** (`@CreatedDate`, `@LastModifiedDate`)에서 `LocalDateTime`이 기본 타입으로 사용됨
- REST API JSON 응답 시, `@JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss")` 어노테이션과 함께 날짜 직렬화/역직렬화에 필수적으로 활용

## 4. 익명 클래스 (Anonymous Class) & 람다 (Lambda)

### 개념
**익명 클래스(Anonymous Class)** 는 이름이 없는 지역 클래스를 선언과 동시에 인스턴스화하는 방식이다.

- 특정 부모 클래스를 상속하거나 인터페이스를 구현해야 함
- **일회성으로 사용할 간단한 구현체(코드 조각)를 전달**할 때 유용

**Java 8** 이후, 익명 클래스 작성의 번거로움을 줄이기 위해 **람다(Lambda) 표현식**으로 발전하였다.

### ☕ 비유
> **"일회용 종이컵"** — 공장에서 정식으로 이름표를 붙인 머그컵(일반 클래스)을 만들지 않고, 지금 한 번 쓰고 버릴 목적으로 그 자리에서 빠르게 만들어 쓰는 컵이다.

### 예시 코드
```java
// 익명 클래스: 인터페이스 구현체를 그 자리에서 정의
hello(new Process() {
    @Override
    public void run() {
        System.out.println("주사위 굴리기 로직 실행");
    }
});

// 람다(Lambda): Java 8 이후, 위 코드를 간결하게 리팩토링
hello(() -> {
    System.out.println("주사위 굴리기 로직 실행");
});
```

### 🌱 실제 Spring에서의 활용
- **Spring Security**에서 `SecurityFilterChain` 설정 시 콜백으로 사용
- **JdbcTemplate**에서 DB 데이터를 객체로 매핑하는 `RowMapper` 구현 시 사용
- 현대 Spring Boot 프로젝트에서는 익명 클래스 대신 **람다 표현식**으로 간결하게 대체하여 작성
