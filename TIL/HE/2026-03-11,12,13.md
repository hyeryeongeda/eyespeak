### FastAPI TTS 추론 서버 구현 — `tts_server.py`

단순 데모 스크립트가 아닌, 팀 백엔드와 연동 가능한 REST API 서버를 구현했다.

```python
# [PyTorch 호환성 패치]
# TTS 라이브러리 내부가 torch.load 호출 시 weights_only를 명시하지 않아
# PyTorch >= 2.0에서 FutureWarning/오류 발생 → 전역 monkey-patch로 해결
_original_load = torch.load
def _force_unsafe_load(*args, **kwargs):
    if "weights_only" not in kwargs:
        kwargs["weights_only"] = False
    return _original_load(*args, **kwargs)
torch.load = _force_unsafe_load

# [transformers 버전 호환성 패치]
# isin_mps_friendly 함수가 특정 버전에서 제거됨 → torch.isin으로 대체 주입
if not hasattr(_pt_utils, "isin_mps_friendly"):
    _pt_utils.isin_mps_friendly = lambda elements, test_elements, **_: \
        torch.isin(elements, test_elements)
```

```python
# [핵심 버그 해결] StreamingResponse → Response
# StreamingResponse는 Content-Length 헤더를 설정하지 않아
# 브라우저/재생기가 오디오 길이를 0초로 인식하는 버그 발생
# → 전체 bytes 완성 후 Content-Length 명시한 Response로 대체
return Response(
    content=wav_bytes,
    media_type="audio/wav",
    headers={
        "Content-Disposition": "inline; filename=tts.wav",
        "Content-Length": str(len(wav_bytes)),
    },
)
```

```python
# [체크포인트 자동 탐지 — 2단계 fallback]
# 학습 서버와 추론 서버가 분리된 환경을 고려:
# checkpoints/best_model.pth 우선 → 없으면 run/training/ 최신 run 폴더 자동 탐색
def _get_checkpoint_dir():
    if (CHECKPOINTS_DIR / "best_model.pth").exists():
        return CHECKPOINTS_DIR, ...
    dirs = sorted([d for d in RUN_TRAINING.iterdir()
                   if d.name.startswith("GPT_XTTS_")])
    return str(dirs[-1]), ...  # 폴더명에 날짜 포함 → sort만으로 최신 run 특정
```

## 3. KPT Review

### Keep

- 라이브러리 호환성 패치를 코드에 명확히 주석으로 남긴 점 — 향후 라이브러리 업그레이드 시 원인 파악 비용이 0에 가깝다.
- `startup` 이벤트로 모델을 1회만 로드하는 구조 — 요청마다 로드하면 XTTS 기준 약 10초 지연 발생.
- 에폭을 줄여 실험-검증 사이클을 짧게 만든 결정 — 소량 데이터에서 100 에폭은 과적합이 명백하다.
- 체크포인트 자동 탐지 fallback 로직 — 학습 환경과 추론 환경이 분리되어도 서버가 동작한다.

### Problem

- `trained_demo.py`의 `OUTPUT_FOLDER`가 하드코딩되어 재학습 시 수동 수정 필요. `tts_server.py`의 자동 탐지 로직이 적용되지 않은 상태.
- `trained_demo.py`의 `target_text`가 빈 문자열(`""`)로 남아 있어 실행 전 반드시 수동으로 채워야 함.
- `wavs/` 디렉토리가 현재 비어 있어 서버 기동 시 화자 레퍼런스 파일(`wavs/audio1.wav`) 오류 발생.
- 합성 파라미터(`temperature`, `top_k` 등)가 하드코딩되어 API 요청으로 조정 불가.

### Try

- `trained_demo.py`에 argparse 추가 — `--text`, `--checkpoint` 인자로 CLI에서 직접 제어.
- `build_dataset.py`에 세그먼트 필터링 옵션 추가 — `segment.avg_logprob < -1.0` 기준으로 Whisper 저신뢰도 구간 자동 제거.
- 실제 화자 음성으로 `build_dataset.py` 실행 → 최소 30개 이상 고품질 세그먼트 확보 후 재학습.

## 4. Deep Dive & Learning (오늘의 배움)

| 개념 | 내용 |
|------|------|
| **`StreamingResponse` vs `Response`** | `StreamingResponse`는 `Content-Length` 없이 청크 전송 → 미디어 재생기가 길이를 0으로 인식. 완성된 bytes가 있다면 `Response + Content-Length` 명시가 올바른 선택. |
| **PyTorch `weights_only` 보안 옵션** | PyTorch ≥ 2.0에서 `torch.load`는 `weights_only=True` 권고. 레거시 라이브러리는 이를 명시하지 않아 경고 발생 → 전역 monkey-patch가 유효한 우회 패턴이지만, 라이브러리가 업데이트되면 제거해야 함. |
| **소량 데이터 파인튜닝 과적합** | 15개 샘플 × 100 에폭 = 동일 데이터 수백 번 반복 → 훈련 문장은 잘 읽히지만 새 문장에서 발음 불안정. 20~30 에폭이 일반화에 유리하며, 데이터를 먼저 늘리는 것이 근본 해결책. |
| **`repetition_penalty=5.0`의 역할** | 자기회귀 TTS가 특정 음절을 반복 생성하는 경향을 억제. 이미 생성된 토큰의 logit을 나눠 확률을 낮춤. 받침이 없는 개음절이 많은 한국어 TTS에서 특히 중요. |
| **`faster-whisper`의 `avg_logprob`** | 세그먼트별 평균 로그 확률. `-1.0` 이하면 인식 신뢰도가 낮은 구간으로, 이를 기준으로 노이즈/무음 세그먼트를 자동 필터링하면 학습 데이터 품질을 높일 수 있음. |
