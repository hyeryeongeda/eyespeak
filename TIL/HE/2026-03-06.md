# TIL 회고 - 2026.03.06



### 1. YOLO+CNN → MediaPipe FaceMesh 전환 결정

전날까지는 YOLOv8으로 눈을 검출하고 동공 centroid를 추적하는 방식으로 작업했습니다. 하지만 이 방식은:

- CNN 시선 모델이 사람마다 달라 일반화 불가
- 739px 오차로 실사용 불가
- ONNX 모델 로드 지연 (44MB `best.onnx`)

→ **MediaPipe FaceMesh의 내장 홍채 랜드마크(468~476번 포인트)를 직접 사용**하는 방식으로 전환. 별도 학습 모델 없이 브라우저에서 바로 동작.

### 2. RBF 캘리브레이션 구현

단순 2차 다항식 회귀에서 **RBF(Radial Basis Function) 보간법**으로 고도화:

- 4D 홍채 feature `[lnx, lny, rnx, rny]` → 화면 좌표 (x, y) 매핑
- Gaussian RBF 커널 + Tikhonov 정규화 (`λ=1e-4`)으로 안정적인 역행렬 계산
- 25점 캘리브레이션(5×5 그리드), 점당 0.5s 안정화 + 1.2s 수집 = 총 약 42초
- 직접 Gauss-Jordan 소거법으로 선형 시스템 풀기 (외부 라이브러리 없이 순수 JS)

### 3. ALS AAC 용 9분할 UI 설계 및 구현

- 3×3 그리드: 감정 / 요청 / 통증 / 기호 / **[중앙=카메라/휴식]** / 후보 / 삭제 / 전체 지우기 / SOS
- 가운데 타일 = 원형 카메라 화면 + 휴식 영역 (선택 없음)
- **Dwell 선택**: 시선을 타일에 고정하면 게이지(링 애니메이션)가 차고 1600ms 후 선택
- **더블 블링크**: 눈 깜빡임 2회(800ms 이내) → 뒤로가기 트리거

### 4. 눈 깜빡임 검출 로직

- EAR(Eye Aspect Ratio) 방식: `(top - bot) / (cornerA - cornerB)` 거리 비율
- `blinkClosedRatio = 0.55` 임계값, 250ms 쿨다운, 800ms 더블 블링크 윈도우
- 눈 감긴 상태 안정 판정 후 더블 블링크 카운트

### 5. UX 세부 구현

- 토스트 알림, 드웰 링 conic-gradient 애니메이션
- `[` / `]` 키로 dwell 시간 실시간 조절
- `C` 키 재캘리브레이션, `D` 키 로그 출력
- 시작 오버레이 → 캘리브레이션 → 운용 3단계 state machine
- HUD: Face/Iris 감지 상태, L/R 홍채 px 위치, 눈 열림 비율 실시간 표시

## KPT 회고

### Keep (잘 된 것, 계속할 것)

- **외부 라이브러리 최소화**: RBF, 행렬 연산, 캘리브레이션 모두 순수 JS로 직접 구현 → 배포 의존성 0
- **ALS 환자 관점 UX 고려**: 더블 블링크 뒤로가기, 휴식 영역, SOS 바로가기 등 실사용 시나리오 반영

### Problem (문제점, 개선 필요)

- **RBF sigma 하드코딩**: `rbfSigma` 값이 고정돼 있어 캘리브레이션 데이터 분포에 따라 성능 편차 발생 가능. 데이터 기반 자동 설정 필요
- **눈 깜빡임 vs 의도 구분**: 자연 눈 깜빡임과 더블 블링크 명령이 혼동될 수 있음. 특히 건조한 눈에서 오작동 위험
- **타일 내용이 아직 플레이스홀더**: "감정", "요청" 등 카테고리만 있고 서브 메뉴 구조 미구현

### Try (다음에 시도할 것)

- **계층형 이모지 메뉴 구현**: 1단계 카테고리 선택 → 2단계 구체적 이모지/문구 선택으로 확장
- **캘리브레이션 단축**: 9점 또는 적응형 캘리브레이션 (오차가 높은 영역만 재수집)
- **TTS(음성 합성) 연동**: 선택된 이모지/문구를 Web Speech API로 음성 출력
- **스크롤 없는 1 page 전체 UI**: 화면 분할 비율 동적 조정으로 모니터 해상도 대응
