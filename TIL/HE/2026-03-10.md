### 2. 사용하는 모델: XTTS v2 (Coqui)

2.1 XTTS v2란?

- **Coqui**에서 만든 **멀티링구얼 TTS** 모델입니다.
- **텍스트** + **짧은 참조 음성(3~6초)**을 주면, 그 **목소리 스타일**로 문장을 읽어 줍니다.
- 한국어(`ko`)를 지원합니다.

2.2 모델 구조 (쉽게)

| 구성 요소 | 역할 |
|----------|------|
| **GPT** | 텍스트와 참조 음성을 보고, "다음에 나올 소리"를 예측. **이 부분만 우리가 학습(파인튜닝)** 합니다. |
| **DVAE** | 오디오를 압축/복원하는 인코더·디코더. **학습하지 않고 고정**해서 씁니다. |
| **Mel stats / Vocoder** | 멜 스펙트럼 정규화, 최종 음성 파형(waveform) 생성. |

즉, **GPT만 우리 데이터로 파인튜닝**하고, 나머지는 원본 XTTS v2 가중치를 그대로 씁니다.

2.3 베이스(원본) 모델

- 학습 전에 **XTTS v2.0** 체크포인트를 자동으로 받아 옵니다.
- 저장 위치: `run/training/XTTS_v2.0_original_model_files/`
- 파일: `model.pth`, `dvae.pth`, `mel_stats.pth`, `vocab.json`

### 3. 사용하는 데이터

3.1 데이터 형태

- **한 명의 화자**가 말한 **긴 음원 1개**를 기준으로 합니다.
- 예: 유튜브 영상 1개, 또는 직접 녹음한 mp3 1개.

3.2 데이터가 만들어지는 과정

```
[원본 음원 1개]  (유튜브 URL 또는 mp3 등)
        ↓
   build_dataset.py
        ↓
[1] 오디오 파일 1개 확보 (yt-dlp 또는 기존 파일)
[2] faster-whisper (large-v3, 한국어) → 구간별 타임스탬프 + 텍스트(자막)
[3] FFmpeg로 구간별 wav 분할 → wavs/audio1.wav, audio2.wav, ...
[4] LJSpeech 형식 메타데이터 생성 → wavs/metadata.txt
```

그래서 **원본 1개**가 **문장 단위 (wav 파일 + 텍스트)** 여러 개로 쪼개집니다.

3.3 LJSpeech 형식 (학습기가 기대하는 형식)

- **wav 파일**: `wavs/audio1.wav`, `wavs/audio2.wav`, … (22.05kHz 등)
- **metadata.txt**: 한 줄에 한 샘플  
  `파일명(확장자 없음)|읽을 텍스트|같은 텍스트`
  - 예: `audio1|흡연하면 천만원 현상금 걸었잖아요|흡연하면 천만원 현상금 걸었잖아요`

학습 스크립트는 이걸 읽어서 **(오디오 경로, 텍스트, 언어)** 리스트를 만들고, 그걸로 GPT를 학습시킵니다.

3.4 데이터 품질이 중요한 이유

- **텍스트와 오디오가 1:1로 맞아야 함** → Whisper 인식 오류가 있으면 잘못된 문장으로 학습되어 발음이 어색해질 수 있음.
- **너무 짧은 구간**, **노이즈/침묵만 있는 구간**은 학습에 불리하므로 제거하거나 필터링하는 것이 좋습니다.

### 4. 학습 (파인튜닝)이 어떻게 이루어지는지

4.1 학습 스크립트

- **`train_gpt_xtts.py`**: XTTS v2의 **GPT 부분만** 우리 데이터로 파인튜닝합니다.

4.2 주요 학습 설정 (코드 기준)

| 항목 | 값 | 설명 |
|------|-----|------|
| 데이터 형식 | LJSpeech | `wavs/` + `wavs/metadata.txt` |
| 언어 | `ko` | 한국어 |
| 에폭 | 100 | 전체 데이터를 100번 반복 학습 |
| 배치 | BATCH_SIZE=2, GRAD_ACUMM_STEPS=128 | effective batch size 256 |
| 참조 음성 길이 | 약 3~6초 | 조건으로 넣는 음성 길이 |
| 문장/오디오 제한 | 텍스트 최대 200자, wav 약 11.6초 | 그 이상은 잘림/제외 |

4.3 학습 결과가 저장되는 곳

- **폴더**: `run/training/GPT_XTTS_v2.0_KO_FT_ep100-날짜시간-해시/`
- **파일**: `best_model_7.pth`, `best_model_14.pth`, … (숫자가 클수록 나중에 저장된, 더 좋은 모델)
- **설정**: 같은 폴더의 `config.json`

가장 마지막에 저장된 `best_model_XXX.pth`가 **최종 best 모델**입니다.

4.4 학습 진행 확인

- **텐서보드**: `tensorboard --logdir=./run/training` 실행 후 브라우저에서 loss 추이 확인

### 5. 어떻게 구현·사용하는지 (전체 흐름)

5.1 한 번에 보는 순서

| 순서 | 작업 | 명령/파일 |
|------|------|-----------|
| 1 | 데이터셋 생성 | `python build_dataset.py --existing_audio ./data/my_voice_audio.mp3` 또는 `--youtube_url "URL"` |
| 2 | 학습 | `python train_gpt_xtts.py` 또는 `python run_pipeline.py` (데이터 있으면 학습만 실행) |
| 3 | 학습 로그 확인 | `tensorboard --logdir=./run/training` |
| 4 | 데모용 체크포인트 준비 | `python prepare_checkpoints_for_demo.py` (best_model → checkpoints/ 복사) |
| 5 | 학습된 목소리로 합성 | `python trained_demo.py` → `save/trained_output_xtts.wav` 확인 |

5.2 데이터셋 생성 (1단계)

```bash
# 기존 오디오 파일로 생성
python build_dataset.py --existing_audio ./data/my_voice_audio.mp3

# 유튜브 영상으로 생성
python build_dataset.py --youtube_url "https://www.youtube.com/watch?v=영상ID"
```

- 결과: `wavs/` 안에 `audio1.wav`, `audio2.wav`, … 와 `wavs/metadata.txt` 생성.

5.3 학습 실행 (2단계)

```bash
# 방법 1: 파이프라인 (데이터 있으면 학습만 실행)
python run_pipeline.py

# 방법 2: 학습만 직접 실행
python train_gpt_xtts.py
```

- 데이터가 없으면 `run_pipeline.py`는 "먼저 데이터셋을 생성하라"는 안내만 출력합니다.

5.4 데모용 체크포인트 준비 (4단계)

- `trained_demo.py`는 **`checkpoints/`** 폴더에서 `best_model.pth`와 `config.json`을 읽습니다.
- 학습 직후에는 `run/training/...` 에만 있으므로 복사가 필요합니다.

```bash
python prepare_checkpoints_for_demo.py
```

- 이 스크립트가 **가장 최근 run 폴더**에서 **가장 큰 번호의 best_model_XXX.pth**를 `checkpoints/best_model.pth`로, `config.json`을 `checkpoints/config.json`으로 복사합니다.

5.5 학습된 목소리로 합성 (5단계)

```bash
python trained_demo.py
```

- **화자 참조**: `wavs/audio1.wav` (학습 시 사용한 레퍼런스)
- **출력 파일**: `save/trained_output_xtts.wav`
- **합성 문장**: `trained_demo.py` 안의 `target_text`를 바꾸면 다른 문장으로 생성 가능

```python
target_text = "여기에 원하는 문장을 넣으세요."
```

5.6 베이스 모델과 비교

- **학습 전 목소리**: `python base_demo.py` → 베이스 XTTS v2 음성
- **학습 후 목소리**: `python trained_demo.py` → 파인튜닝된 "우리 목소리"

두 wav를 들어 보면 개인화 정도를 확인할 수 있습니다.

### 🚀 핵심 로직 및 기술 구현

**최신 학습 run 폴더에서 최대 번호 best_model 자동 선택 및 데모용 복사**

학습 직후 체크포인트는 `run/training/GPT_XTTS_...-날짜시간-해시/` 아래에 `best_model_7.pth`, `best_model_14.pth`, … 형태로 누적된다. 데모 스크립트(`trained_demo.py`)는 `checkpoints/best_model.pth`만 읽기 때문에, **가장 최근 run 폴더**와 그 안에서 **번호가 가장 큰 best_model_XXX.pth**를 자동으로 골라 복사하는 로직이 필요했다.

```python
# prepare_checkpoints_for_demo.py
def find_latest_run():
    """run/training/ 아래에서 가장 최근 학습 run 폴더 찾기 (GPT_XTTS_... 형식)"""
    dirs = [d for d in os.listdir(RUN_DIR) if ... and d.startswith("GPT_XTTS_")]
    dirs.sort()  # 폴더 이름에 날짜+시간 포함 → 정렬 시 최신이 마지막
    return os.path.join(RUN_DIR, dirs[-1])

def find_latest_best_model(run_path):
    """run 폴더 안에서 번호가 가장 큰 best_model_XXX.pth 찾기"""
    files = glob.glob(os.path.join(run_path, "best_model_*.pth"))
    def num(f):
        m = re.search(r"best_model_(\d+)\.pth", os.path.basename(f))
        return int(m.group(1)) if m else 0
    return max(files, key=num)
```

- **왜 이 방식을 선택했는가**: run 폴더명에 타임스탬프가 포함되어 있어 문자열 정렬만으로 최신 run을 얻을 수 있고, best_model 번호는 학습 중 주기적 저장 순서를 반영하므로 `max(..., key=num)`으로 최종 best를 일관되게 선택할 수 있다. 수동 복사 시 실수(잘못된 run/잘못된 번호 선택)를 줄이고, 재학습 후에도 한 번의 `python prepare_checkpoints_for_demo.py`로 데모 환경을 맞출 수 있다.

### 💡 배운 점 (Key Learnings)

- **run 폴더 네이밍**: XTTS 학습 스크립트가 `GPT_XTTS_v2.0_KO_FT_ep100-날짜시간-해시` 형식으로 디렉터리를 생성하므로, `listdir` 후 `sort()`만으로 최신 run을 결정할 수 있음. 별도 mtime 비교 없이도 운영이 가능하다.
- **데모 체크포인트 경로 통일**: 학습 결과는 `run/training/...`에만 있고, `trained_demo.py`는 `checkpoints/`를 참조하므로, 중간 단계(체크포인트 복사)를 문서와 스크립트로 명시해 두면 팀원·재현 시 혼선을 줄일 수 있다.
- **SCP 업로드 대상**: 학습용 데이터(`data/`, `wavs/`), 학습 결과(`run/`)를 구분해 문서화해 두면, 서버에서 재학습·추론만 할 때와 로컬 백업 목적에 맞게 선택적으로 업로드할 수 있다.
