## 2-2. 코사인 유사도 cosine_sim

두 벡터 방향이 얼마나 비슷한지 측정하는 함수인데요, 1에 가까우면 비슷하고, 0에 가까우면 관련 없습니다.

```python
def cosine_sim(a, b):
# np.linalg.norm은 넘파이에서 벡터의 크기(길이) 계산하는 함수입니다.
# 자세한 설명은 댓글로...
	return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b) + 1e-9
```

## 2-3. 시간대 가중치 calculate_temporal_boost

환자가 같은 시간대에 자주 쓴 표현이면 점수를 올려줍니다.

- lastUsed가 데이터에 있으면 현재 시각과 요일과 겹칠 수록 가중치를 조절하는데요
  - lastUsed의 시각이 현재와 같은 시간대다? 그러면 1.2배
  - 같은 요일이다? 그러면 1.1배
  - 그 외에는 1.0으로 변화 안 줍니다.

```python
def_calculate_temporal_boost(item: dict, current_hour: int, current_weekday:int)->float

	last_used = item.get("lastUsed")
	if not last_used:
		return 1.0
	try:
		s = last_used.replaceC("Z","").split("+")[0].strip()
		dt = datetime.fromisoformat(s)
		if dt.hour == current_hour:
			return 1.2

		if dt.weekday() == current_weekday:
			return 1.1

		except Excpetion:
			pass

		return 1.0
```

## 2-4. 유저 문장 검색 search_sentences

추천 로직의 핵심 검색 함수입니다. user_db에서 질문이랑 가장 유사한 문장을 찾아냅니다.

### 어디에 쓰이냐?

- 문장 추천
- 단어 추천
- 개방형 카테고리( 추후 설명)
- 등등 여러 곳에서 재사용됩니다. 서버에서 가장 많이 호출되는 함수입니다.

여기서는 sentiment_filter가 있다(= 감정 분류가 된 문장이다)하면 해당 감정 문장에서만 검색해옵니다.

- 예를 들어 내 mood가 슬프다로 되어있으면 → 문장 추천에 슬프다..mood가 되 문장들만 검색하도록 거르는 과정입니다.

아무튼 유저가 보는 추천 문장을 어떻게 뽑아오는지 그 과정은 아 래와 같습니다.

1. 감정이 있는 문장이라면, 같은 감정인 문장만 뽑아옵니다.
   - 그렇지 않은 경우에는 그냥 전체 문장에서 뽑아옵니다
2. 질문을 벡터로 변환합니다.
3. 벡터로 변환된 질문과 문장의 유사도를 계산합니다.

```python
def _search_sentences(question, user_db, sentiment_filter=None, k=5):
	pool = user_db
	# 1) sentiment_filter가 있으면 거기서만 문장 뽑아오기
	if sentiment_filter:
		filtered = [item for item in user_db if item["sentiment" == sentiment_filter]
		# k개 문장 뽑아오기로 했는데 만약 k개 보다 문장 작으면, 그냥 전체 문장에서 검색해옵니다.
		if len(filtered) >= k:
			pool = filtered


    now = datetime.now()
    current_hour = now.hour
    current_weekday = now.weekday()

	# 2) 이제 질문을 벡터로 변환합니다.
   q_vec = get_embedding(question)

# 3) 벡터로 변환했으니 각 문장과 유사도를 계산합니다.
# 점수는 유사도 X 사용 빈도 가중치 X 시간대 가중치 X 의도(intent) 가중치입니다.
    results = []
    for item in pool:
	# 질문이랑 환자 문장이 얼마나 비슷한 뜻인지 숫자로 계산합니다.
	# 추가한 로직 : 검색 과정에서 현재 질문의 intent_filter랑 유저 db에 있는 문장의 categories를 비교합니다
	# 그래서 의도가 일치하면 intent_boost = 1.5라는 가중치를 곱해줘요
	# 즉, 단순히 감정만 맞는 게 아니라, 아파"라는 통증 의도 질문에
	# 무릎 쑤셔 라는 통증 카테고리 문단이 상다네 더 자주 노출돼요
        sim = cosine_sim(q_vec, get_embedding(item["text"]))
        base_score = sim * item["weight"]
        temporal_weight = _calculate_temporal_boost(item, current_hour, current_weekday)
        intent_boost = 1.5 if (intent_filter and item.get("categories") and intent_filter in item["categories"]) else 1.0
        results.append({
            "text":   item["text"],
            "score":  base_score * temporal_weight * intent_boost,
            "source": item["source"],
        })


	# 점수가 높은 대로 문장 정렬하고, 중복 문장 없앤 뒤에 딱 필요한 개수(k)개만 뽑아냅니다.
	seen, deduped = set(), []
	for r in sorted(results, key=lambda x: x["score"], reverse=True):
	# 똑같은 문장 안들어가도록 검사함
		if r["text"] not in seen:
			seen.add(r["text"])
			deduped.append(r)
		return deduped[:k] # 중복 없앤 전체 목록에서 위에서부터 k개까지만 잘라서 반환함


```

def _search_general(question: str, k: int= 3, sentiment_filter: str | None = None)-> list:

## 2-6. 혼합 검색 _serach_sentences_mixed_

user_db랑 general_db를 50:50으로 섞어서 검색합니다. sentiment가 있으면 양쪽 모두 같은 감정만 검색합니다.

- 이때 질문 or 주제가 감정과 관련된 문장이다? (sentiment 포함 O)
  - general_db에 sentiment있으면 유저 50 일반 문장 50 이 비율로 가져옵니다.
  - general db에 sentiment 없으면 그냥 유저에서 다 가져옵니다 (이 편이 그럴듯한 답변을 가져올 확률이 높음)
- 질문이 감정과 관련된 문장 아니다(sentiment 포함 X)
  - 그러면 그냥 유저랑 일반 DB에서 반반씩 가져옵니다

### 예상 질문 : 왜 user_db에서 추천 문장 다 안 가져왔느냐?

- 처음에는 user_db에서 가져왔으나 유저 더미 데이터셋이 일반 데이터셋의 10분의1 도 안되는 크기다보니 질문과 관련 없는 문장도 억지로 가져오는 느낌이 들었습니다.
- 유저 최적화 답변을 가져오는 것도 중요하지만, 질문과 관련된 답변을 가져오는 것도 중요하다고 판단하여 임의로 비율을 50 대 50으로 설정하여 가져오고 있습니다.
  - 당연히 유저 더미 데이터셋 커지면 추후 수정 가능합니다.

```python
def _search_sentences_mixed(question: str, user_db:list, sentiment_filter:str | None = None, k_total: int= 6) -> list:
	if sentiment_filter is not None:
		general_has_sentiment = general_db and "sentiment" in general_db[0] # 일반 db 첫번째 항복에 sentiment라는 키(감정 있는지 없는지) 확인
		if general_has_sentiment:
			k_user = (k_total + 1) // 2
			k_general = k_total - k_user
			# 환자가 예전에 썼던 문장 중에서, 보호자가 한 질문이랑 감정이 맞는 문장들을 담는 중
			user_candidates = _search_sentences(question, user_db, None, k=k_user)
			# 일반 db에서 질문이랑 감정이 맞는 문장을 참아서 담는 중
			general_candidates = _search_general(question, k=k_general)
			merged = user_candidates + general_candidates
			return merged[:k_total]
```

판별 과정은 아래와 같습니다.

1. 보호자 질문이 들어온다
2. LLM이 질문 유형을 판별한다
3. 카테고리 + SENTIMENTmAP을 생성한다
4. 호출은 1회로 통합한다.

## 4-2. LLM 후처리

### Temperature

모델 답변 생성할 때 가미하는 창의성이라고 생각하면 되는데

### tokens

## 5-2. keywords 추출 extract_keywords_from_similar

유사 문장의 키워드 필드에서 카테고리에 맞는 단어를 추출해요.

### 예상 질문

-다로 끝나는 애들을 서술어로 넣어버리면, 바다와 같은 명사도 서술어로 들어가지 않나요?

- 맞습니다. 다만 다중 필터링 구조 때문에 그렇게까지 이어지지 않아요
- 1차 추출에서 ‘바다’가 서술어에 잘못 들어가도, 2단계인 llm_filter_words 함수에서 llm이 다시 후보 단어 검사해요. 이때 후보 중에 서술어로 쓸 동사만 골라줘 이런 식으로 명령하기 때문에, 최종 목록에서 걸러내요
- 그리고 OKT를 설치해서 실행하면, extract_words_by_pos 함수가 실행되는데요.
- 이 함수는 품사 태그(noun, verb)를 기준으로 명사와 동사를 분리해서 후보군을 보완합니다.

```python

def _extract_keywords_from_similar(similar_results: list, user_db: list, category: str) -> list:
    """유사 문장의 keywords에서 카테고리에 맞는 단어 추출 (빈도순).
    similar_results: _search_sentences의 반환값 (외부에서 한 번만 호출해서 전달).
    - subjects/objects → "다"로 안 끝나는 것 (명사)
    - verbs → "다"로 끝나는 것 (동사/형용사)"""

    similar_texts = {s["text"] for s in similar_results}
    counter = Counter()
    for item in user_db:
	    if item["text"] in similar_texts:
		    for kw in item.get("keywords",[]):
			    if not kw:
				    continue
				  is_verb = any(kw.endswith(s) for s in VERB_SUFFIXES)
				  if category == "verbs" and is_verb:
					  counter[kw] += 1
					elif category in ("subjects", "objects") and not is_verb:
						counter[kw] += 1
		return [w for w, _in counter.most_common()]

```

````python

    - subjects → 주어로 쓸 수 있는 명사 (사람, 신체부위 등)
    - objects → 목적어로 쓸 수 있는 명사 (사물, 음식, 장소 등)
    - verbs → 서술어로 쓸 수 있는 동사·형용사
    실패 시 후보를 그대로 반환."""
    if not candidates:
        return []

    # 캐시 확인: 같은 질문+카테고리면 LLM 호출 생략
    cache_key = (question.strip(), category, tuple(candidates))
    if cache_key in _word_filter_cache:
        return _word_filter_cache[cache_key]

    category_desc = {
        "subjects": "주어로 쓸 수 있는 명사(사람, 신체부위 등)만",
        "objects": "목적어로 쓸 수 있는 명사(사물, 음식, 장소, 행위 대상 등)만",
        "verbs": "서술어로 쓸 수 있는 동사·형용사만 (원형, '다'로 끝나는 형태)",
    }.get(category, "적절한 단어만")

    prompt = f"""보호자 질문: "{question}"
후보 단어: {json.dumps(candidates, ensure_ascii=False)}

위 후보 중에서 {category_desc} 골라주세요.
- 부사(많이, 아직도, 오늘 등), 어미, 조사, 감탄사는 제외
- 해당하는 단어가 없으면 빈 배열 []
- JSON 배열만 출력, 다른 텍스트 없이"""

    try:
        resp = llm_client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[
                {"role": "system", "content": "JSON 배열만 출력하세요."},
                {"role": "user", "content": prompt},
            ],
            max_tokens=150, temperature=0.1,
        )
        raw = (resp.choices[0].message.content or "").strip()
        # 마크다운 코드블록 제거
        for prefix in ("```json", "```"):
            if raw.startswith(prefix):
                raw = raw[len(prefix):].strip()
        if raw.endswith("```"):
            raw = raw[:-3].strip()
        result = json.loads(raw)
        if isinstance(result, list):
            # 후보에 있던 것만, 후보 순서 유지
            candidate_set = set(candidates)
            filtered = [w for w in result if isinstance(w, str) and w in candidate_set]
            _word_filter_cache[cache_key] = filtered
            return filtered
    except Exception as e:
        print(f"[LLM 단어 필터 실패] {e}")

    # LLM 실패 시 후보 그대로 반환 (캐싱 안 함 → 다음에 재시도)
    return candidates
````

## 5-5. pastWords 보충 + 맥락 연결 (context_boost)

llm 필터 후에 단어가 4개 미만이면, pastWords에서 나머지를 채웁니다. 이때 ㅣ전 단계에서 선택한 단어와의 유사도도 점수에 반영합니다.

```python
_WORD_CONTEXT_ALPHA = 0.4 # 맥락 반영 강도

def score(w):
	base = cosine_sim(q)vect, get_embedding(w))
	norm_freq = word_usage_freq.get(w, 0) / max_freq) if max_freq else 0
	base = sim * (1.0 + 0.5 * norm_freq)
	context_boost = 1.0
	if selected_vectors:
		w_vec = get_embedding(w)
		context_boost = 1.0 + _WORD_CONTEXT_ALPHA * max((cosine_sim(sv, w_vec) for sv in selected_vectors), default=0.0)
        return base * context_boost
```

# 6. 단어로 문장 생성

환자가 선택한 단어들을 문장으로 넘겨서 문장 3개를 생성해요. 문장 부호랑 내용 단어를 분리해서 프롬프트에 넣습니다

- LLM:만약 LLM이 실패하면 verb_map( 동사 활용 사전 12개)로 단어 이어붙인 fallback 문장 생성해요

```python
def _generate_from_words(words: list, question: str) -> list:
    """선택된 단어들로 문장 3개 생성"""
    punct_set     = {".", "!", "?"}
    punct         = "".join(w for w in words if w in punct_set)
    content_words = [w for w in words if w not in punct_set and w != "없음"]

    prompt = f"""보호자 질문: "{question}"
선택된 단어: {', '.join(content_words)}
문장 끝 부호: {punct if punct else '없음'}

위 단어들로 환자가 답할 법한 자연스러운 한국어 문장을 정확히 3개 만드세요.
- 보호자 질문 시제에 맞게 (과거형/현재형)
- 반말 구어체, 15자 이내
- 지정된 문장 부호로 끝내기
- 번호나 기호 없이 줄바꿈으로만 구분하여 3개 출력"""
    try:
        resp = llm_client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[
                {"role": "system",  "content": "ALS 환자 답변 생성 전문가. 요청한 개수만큼만 출력."},
                {"role": "user",    "content": prompt},
            ],
            max_tokens=120, temperature=0.8,
        )
        lines = [s.strip() for s in resp.choices[0].message.content.strip().split("\n") if s.strip()][:3]
    except Exception:
        lines = []

    verb_map = {
        "응원하다": "응원했어", "보다": "봤어", "좋아하다": "좋아했어",
        "싫어하다": "싫었어",  "먹다": "먹었어", "마시다": "마셨어",
        "듣다": "들었어",      "생각하다": "생각했어", "즐기다": "즐거웠어",
        "기억하다": "기억해",  "쉬다": "쉬었어", "힘들다": "힘들었어",
    }
    fallback = " ".join(verb_map.get(w, w) for w in content_words if w) + punct
    while len(lines) < 3:
        lines.append(fallback or "응")
    return lines
```

```python
@app.route("/expressions/use", methods=["POST"])
def record_expression_use():
    """표현 사용 기록 → 파일 갱신 + 캐시 무효화.
    body: user_id(선택), text(필수), sentiment(선택), intent(선택).
    intent가 있으면 pastExpressions 항목의 categories에 저장되어 이후 intent_boost 검색에 반영됨."""
    data = request.json or {}
    user_id = data.get("user_id", DEFAULT_USER_ID)
    text = (data.get("text") or "").strip()
    if not text:
        return jsonify({"error": "text 필수"}), 400
    path = _get_user_file_path(user_id)
    if not path:
        return jsonify({"error": "user not found", "user_id": user_id}), 404
    try:
        with open(path, "r", encoding="utf-8") as f:
            user_raw = json.load(f)
    except Exception as e:
        return jsonify({"error": "file read failed", "detail": str(e)}), 500
    expressions = user_raw.get("pastExpressions", [])
    now_iso = datetime.now().isoformat(timespec="seconds")
    found = False
    for item in expressions:
        if (item.get("text") or "").strip() == text:
            item["usageCount"] = item.get("usageCount", 0) + 1
            item["lastUsed"] = now_iso
            if data.get("sentiment"):
                item["sentiment"] = data["sentiment"]
            if data.get("intent") and data["intent"] not in item.get("categories", []):
                item.setdefault("categories", []).append(data["intent"])
            found = True
            break
    if not found:
        expressions.append({
            "text": text,
            "sentiment": data.get("sentiment", "중립"),
            "categories": [data["intent"]] if data.get("intent") else [],
            "keywords": _auto_generate_keywords(text),
            "usageCount": 1,
            "lastUsed": now_iso,
        })
    user_raw["pastExpressions"] = expressions
    try:
        with open(path, "w", encoding="utf-8") as f:
            json.dump(user_raw, f, ensure_ascii=False, indent=2)
    except Exception as e:
        return jsonify({"error": "file write failed", "detail": str(e)}), 500
    _invalidate_user_cache(user_id)
    return jsonify({"ok": True, "message": "expression recorded", "user_id": user_id})
```
