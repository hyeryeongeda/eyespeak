1. # 임베딩 검색 기능 구현 및 트러블 슈팅 
## Bi-encoder 단독 사용 시 유저가 자주 사용하는 문장이 일반 말뭉치 데이터셋에 비해 잘 반영이 되지 않는 문제 발생

### 첫번째 시도
- 문장이 general_db에 밀리는 현상 발생. usage_count 기반 가중치를 cosine similarity에 곱하는 방식으로 user 문장의 우선순위를 높였으나, 질문 주제와 user_db 주제가 다를 경우 cosine_sim 자체가 낮아 가중치 효과 없음을 확인했다.

따라서 쿼터 분리 방식(user_k + general_k) 도입을 했다. 


### 두번째 시도
두번째 시도를 통해 유저의 특성을 반영하는 데는 성공하였지만, 주제와 무관 user 문장이 강제 포함되는 트레이드오프 발생했다.
- 따라서 Bi-encoder 쿼터 분리 후 Cross-encoder 재랭킹을 2단계로 적용하면 무관한 문장이 재랭킹 과정에서 자연스레 걸러지는 것을 확인했다. 따라서 해당 조합으로 설계를 확정했다.

### 보완 1
- Cross-encoder를 단어 검색에 적용하는 건 비효율적임을 확인. 단어는 후보가 12개뿐이고 텍스트가 1-2어절로 짧아 Cross-encoder가 판단할 문맥이 부족하다. Bi-encoder만으로 충분하다.

## 보안 2
- LLM이 후보 문장을 참고해 새 문장을 생성하던 방식을 변경했다. 기존에는 창작에 가까운 문장이 나와 유저 표현에서 멀어지는 문제가 있었다. 후보 top 3 중 시제·어투(반말/존댓말)만 보정하는 방식으로 교체했다.

## 보완 3
als_patient_dataset.json 로딩 시 list를 dict로 잘못 읽는 AttributeError 발생. 기존 user_sentences2.json은 dict 최상위 구조였으나 als 파일은 list 구조임을 확인, 파싱 로직을 수정해 해결했다.


## 보완 4
보호자 질문 카테고리가 항상 4개 고정 + 감정 매핑 오류 발생. LLM 프롬프트를 질문 유형별로 2-4개 유동 생성 + sentimentMap까지 함께 반환하도록 수정하고, 프론트에서 하드코딩된 감정 매핑 대신 LLM 반환값을 직접 사용해 해결했다.
