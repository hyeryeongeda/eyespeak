## 1. 연구 근거 (원천 자료)

### 근거 1: OHSU 연구 — ALS 환자 AAC 기기 사용 목적 빈도

- **논문**: Dougherty & Lewis (2006), "Purposes of AAC Device Use for Persons with ALS as Reported by Caregivers"
- **출처**: https://pubmed.ncbi.nlm.nih.gov/17114164/
- **대상**: ALS 환자 26명을 돌보는 보호자 34명
- **도구**: Communication Device Use Checklist (17개 의사소통 목적 항목, Light의 분류 프레임워크 기반)

**가장 빈번하게 사용되고 중요하다고 평가된 상위 3개 목적:**

| 순위 | 사용 목적 | 설명 |
|------|-----------|------|
| 1 | 기본 욕구 충족 (Getting needs met) | 식사, 음료, 화장실 등 신체적 필요 전달 |
| 2 | 지시/요청 전달 (Giving instructions or directions) | 보호자에게 구체적 행동 요청 |
| 3 | 욕구 명확화 (Clarifying needs) | 전달된 요구의 재확인, 수정 |

**추가로 일관되게 사용이 보고된 목적:**
- 사회적 유대 유지 (Social closeness)
- 중요 사안 논의 (Information transfer)

### 근거 2: PMC 간호 연구 — 환자 의사소통 핵심 영역

- **논문**: Happ et al. (2021), "Improving Patient Safety and Patient-Provider Communication"
- **출처**: https://pmc.ncbi.nlm.nih.gov/articles/PMC8188878/

**환자 의사소통의 핵심 4개 영역:**

| 순위 | 영역 | 핵심 평가 항목 |
|------|------|--------------|
| 1 | 통증/불편감 (Pain and discomfort) | 임상 중요도 1위 |
| 2 | 도움 호출 (Summoning help) | 독립적 도움 요청 |
| 3 | 감정 표현 (Feelings) | 정서적 소통 |
| 4 | 케어 참여 (Care participation) | 돌봄 과정 참여 |

### 근거 3: 임상 AAC 보드 범용 카테고리

- **출처**: Medical SLPs, EatSpeakThink, Patient-Provider Communication Network
- **대상**: 신경학적 질환 환자 대상 간호시설/재활병원용 보드

**공통 카테고리**: 기본 욕구, 통증/불편, 감정, 환경, 자세/이동, 위생

**핵심 설계 원칙 — Core-Fringe 어휘 구조:**
- Core Vocabulary: 고빈도 표현을 첫 화면에 배치
- Fringe Vocabulary: 저빈도 표현을 하위 페이지에 배치

## 2. 전체 설계 원칙

### 4분할 아이트래킹
- MVP 입력 방식: 시선추적으로 4개 영역 중 하나를 선택
- **모든 화면은 선택지 4개로 구성**

### 3+1 Pagination
- 항목이 4개를 초과할 때: 3개 콘텐츠 + 1개 네비게이션("다른 선택→")
- Core-Fringe 원칙에 따라 고빈도 항목을 첫 페이지에 배치

### Motor Planning Consistency
- 동일한 표현은 항상 같은 위치에 존재
- 반복 사용 시 환자가 운동 기억을 형성하여 빠르게 접근 가능
- **빈도 기반 자동 재배치 금지** — 위치가 바뀌면 motor memory 무력화

## 5. 특화 소통 — 카테고리별 표현 선별 근거

### 표현 선별 공통 원칙
- 보호자가 되물어볼 수 있는 세부 선택지는 제외
- 환자가 **먼저 의사를 전달**해야 하는 핵심 표현만 포함
- 각 카테고리 내에서도 Core-Fringe 구조 적용 (고빈도 표현을 1쪽에)

### 5-1. 화장실·위생

| 페이지 | 표현 | 근거 |
|--------|------|------|
| 1쪽 (요청 개시) | 소변이요 | WTCS: 소변기 준비는 비교적 간단 |
| | 대변이요 | WTCS: 변기 배치+체위 변경+프라이버시 확보 필요 — 소변과 준비 과정 완전히 다름 |
| | 기저귀 갈아주세요 | 기저귀 사용 환자의 핵심 요청 |
| 2쪽 (사후 처리) | 다 했어요 | 완료 신호 — 보호자 대기 해제 트리거 |
| | 씻겨주세요 | NCBI Ch.5: 회음부 관리 필수 |
| | 양치하고 싶어요 | 구강 위생 요청 |

**배제**: "급해요" (행동 정보 없음, 소변이요/대변이요가 이미 긴급 요청), "화장실 가고 싶어요" (ALS 와상 환자는 bedpan/기저귀 사용)

| 페이지 | 표현 | 근거 |
|--------|------|------|
| 1쪽 (전신 체위) | 일으켜주세요 | NCBI Ch.13: Fowler's position. 식사·호흡 시 필수 |
| | 눕혀주세요 | Supine position 복귀. 일으켜주세요의 역방향 |

## 6. 불편 부위 — 3단계 드릴다운 설계

### 왜 3단계인가?
PMC 2021: 통증은 **부위 + 상세 위치 + 강도/유형** 3가지 정보가 모두 전달되어야 의미가 있다.

### 3단계 흐름

**1단계 — 대분류 부위 (4분할, pagination 없음):**
- 머리/목, 가슴/배, 팔/어깨, 허리/다리

**2단계 — 상세 부위 (4분할, pagination 없음):**
- 대분류별 4개 세부 위치
- 예) "가슴/배" → 가슴, 윗배, 아랫배, 옆구리

**3단계 — 강도/유형 (4분할, pagination 없음):**
- 많이 아파요, 조금 아파요, 따끔/저림, 간지러워요

### 왜 텍스트 나열이 아닌가?
기존 방식("머리가 아파요", "배가 아파요"...)은 15개 표현을 5페이지에 나열해야 한다.
3단계 드릴다운은 **최대 3회 선택**으로 4×4×4=64가지 조합 표현 가능.

## 7. 확장 소통 — 2-Stage 추천 파이프라인

### 구조
확장 소통 메인 화면은 4분할: **AI 추천 3개 + 직접 만들기 1개**

### AI 추천 — 2-Stage 추천 파이프라인

#### Stage 1 — 5-Signal Scoring (후보 축소)
150개 전체 표현 풀에서 5가지 신호를 가중 합산하여 상위 K개(기본 10개) 후보를 추출.

| 신호 | 설명 |
|------|------|
| **T (Time)** | 현재 시간대(아침/낮/저녁/밤)에 해당 표현이 사용된 빈도 비율. 시간대 맥락 반영 |
| **F (Frequency)** | 전체 사용 횟수. 절대적 사용 빈도 반영 |
| **R (Recency)** | 마지막 사용으로부터 경과 시간의 역수. 최근 관심사 반영 |
| **S (Sequence)** | 직전 표현 이후 전이 확률 (마르코프 체인). 대화 흐름 예측 |
| **P (Preference)** | 추천되었을 때 실제 선택된 비율. 사용자 선호 학습 |

각 신호는 0-1 정규화 후 가중치(w_t, w_f, w_r, w_s, w_p)로 합산.

**참고**: IJCAI 2022 — Multi-Signal 기반 추천 스코어링 모델

#### Stage 2 — LLM Re-ranking (최종 정렬)
Stage 1의 상위 K개 후보를 LLM에 전달하여, 환자 프로필(나이, 병기, 선호)과 현재 맥락(시간, 최근 대화)을 고려한 최종 3개를 선정.

- 프롬프트에 환자 프로필 + 후보 리스트 + 최근 사용 이력을 포함
- LLM이 후보를 재정렬하고 상위 3개를 JSON으로 반환

**참고**: arXiv 2024 — LLM4Rerank: LLM 기반 Re-ranking이 전통적 정렬 대비 맥락 이해에서 우수

#### 콜드 스타트 (사용 이력 없을 때)
신규 환자는 F, R, S, P 신호가 모두 0. 시간대(T) 기반 기본 추천으로 폴백.

| 시간대 | 추천 |
|--------|------|
| 아침 (6-11시) | "약 먹을 시간이에요", "오늘 컨디션 괜찮아요", "창문 열어주세요" |
| 낮 (11-17시) | "TV 틀어주세요", "물 마시고 싶어요", "전화하고 싶어요" |
| 저녁 (17-22시) | "가족 보고 싶어요", "음악 틀어주세요", "오늘 고마웠어요" |
| 밤 (22-6시) | "잠이 안 와요", "불 꺼주세요", "숨이 답답해요" |

#### 기술 구현
2-Stage 파이프라인은 Spring Boot 백엔드에 통합하여 REST API로 제공 예정.

## 8. 확장 소통 — 직접 만들기 (D방식 카테고리형 빌더)

### 구조
순차적 3단계 플로우: **주제(Topic) → 세부(Detail) → 의도(Intent)** → AI 완성 문장 선택

### 왜 카테고리형(D방식)인가?
최종 문장은 AI가 생성하므로, 입력은 문법 구조(SOV)가 아닌 **의미 힌트**만 전달하면 된다.

### 대안 비교

| 방식 | 설명 | 판정 |
|------|------|------|
| A. 문법형(SOV) | 주어→목적어→서술어 | "엄마가 전화를 주세요" 같은 부자연스러운 조합 발생. AI가 문장 만드는데 문법 입력 강제 불필요 |
| B. 2단계 플랫형 | 대상→의도 | 단계 수는 적으나, 대상 32개를 8페이지에 나열 → 저빈도 항목 접근에 많은 스크롤 |
| C. 키워드형 | 자유 키워드 조합 | 시선 입력으로 키워드 검색 불가 |
| **D. 카테고리형 (채택)** | 주제→세부→의도 | 4개 주제로 먼저 분류 → 저빈도 항목도 최대 3단계(주제+2페이지) 안에 도달 |

### D방식의 장점

1. **Motor Planning Consistency**: 동일한 표현은 항상 같은 경로(주제→세부→의도)로 도달. 반복 사용 시 운동 기억 형성.
2. **Light 1988 매핑**: AAC 의사소통 4대 목적 — Needs & Wants(물건·활동), Information Transfer(상태), Social Closeness(사람), Social Etiquette(사람·상태). 4개 주제가 이 분류에 자연스럽게 대응.
3. **조합 수**: 사람(8×6) + 물건(12×6) + 활동(6×6) + 상태(6×6) = **192가지** 의미 조합. AI가 각 조합에서 자연스러운 문장 3개를 생성.

### 4개 주제 및 선택지

| 주제 | 세부 항목 | 의도 |
|------|----------|------|
| 👤 사람 | 엄마, 아빠, 가족, 간병인, 의사, 친구, 아이, 손님 | 보고 싶어요, 불러주세요, 전화해주세요, 같이 있어주세요, 언제 와요?, 고마워요 |
| 📦 물건 | 물, 밥, 약, TV, 전화기, 음악, 이불, 옷, 안경, 휴지, 책, 사진 | 주세요, 치워주세요, 가져다주세요, 틀어주세요, 꺼주세요, 바꿔주세요 |
| 🎯 활동 | 산책, 외출, 운동, 목욕, 대화, 게임 | 하고 싶어요, 그만할래요, 도와주세요, 언제 해요?, 준비해주세요, 시작해주세요 |
| 💭 상태 | 피곤해요, 심심해요, 불안해요, 궁금해요, 답답해요, 기분 좋아요 | 알려주세요, 도와주세요, 어떡해요?, 괜찮아요, 힘들어요, 나아졌어요 |

### AI 완성 문장
주제+세부+의도 3개 힌트를 LLM에 전달하면, 한국어 자연어 문장 3개를 생성.
프로토타입에서는 템플릿 기반 생성, 실제 서비스에서는 LLM API 활용.

## 9. 보호자 커스터마이징 원칙

### 원칙: pagination 유무에 따른 커스텀 범위

| 화면 유형 | 커스텀 여부 | 이유 |
|-----------|-----------|------|
| **pagination 없는 화면** (4분할 1화면) | **고정** | 모든 선택지가 한 화면에 보이므로 순서 변경의 실익 없음. 오히려 환자의 위치 기억(motor planning)을 혼란시킬 수 있음 |
| **pagination 있는 화면** (3+1 구조) | **보호자 커스텀** | 1쪽에 있느냐 2쪽에 있느냐가 추가 선택 횟수 차이로 직결. 환자의 눈 피로도에 직접 영향 |

### 커스텀 대상

- **카테고리 순서** (7개 카테고리, 3페이지): 어떤 3개가 첫 페이지에 오는지를 보호자가 설정
- **카테고리 내 표현 순서** (6개 표현, 2페이지): 각 카테고리 내에서 어떤 3개가 첫 페이지에 오는지를 보호자가 설정

### 커스텀 비대상

- 불편 부위 각 단계 (Lv1 대분류, Lv2 상세, Lv3 강도) — 모두 pagination 없이 4분할 1화면
- 메인 페이지 4분할
- 확장 소통 메인 (추천3 + 직접 만들기)
- 직접 만들기 Step 1 주제 (4개)

### 기대 효과
연구 근거 기반 초기 배치 + 개인 맞춤 최적화를 동시에 달성하며, 눈 피로도를 최소화.
