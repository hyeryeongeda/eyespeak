# 4단계: 오차 범위 및 UI 스펙

> 3단계 측정 결과를 바탕으로 오차 범위를 정리하고, 버튼/그리드 크기·캘리브레이션·확정 방식을 설계. "이 오차일 때 이 UI 스펙이면 사용 가능한지" 팀/테스터 합의 후 5단계로 진행.

- **4-1**: 3-4(오프라인 정확도)·3-5(실시간 지연) 측정 후 수치를 채우면 됨. 측정 전에는 "측정 후 기입"으로 두고 4-2~4-4부터 정해도 됨.
- **다음 단계**: [5단계 통합·시나리오 테스트](./PHASE5_MVP_SCENARIOS_AND_TEST.md)

## 4-1. 현재 오차 범위 (3단계 결과 기반)

| 항목 | 값 | 비고 |
|------|-----|------|
| **그리드당 각도 오차 (MAE)** | yaw ___°, pitch ___° **(측정 후 기입)** | `measure_offline_accuracy.py` 실행 후 갱신. 참고: 일반 웹캠 gaze MAE 3~8° 수준. |
| **잘못 선택되는 패턴** | **(측정 후 기입)** 예: 경계 인접 그리드로 넘어감, 상단→중앙 편향 등 | 3-4 결과·통합 테스트 노트로 보완 |
| **실시간 떨림** | **(측정 후 기입)** 도 단위 또는 그리드 점프 빈도 | 3-5 또는 침대 시나리오 테스트 시 기록 |

## 4-3. 캘리브레이션·감도

| 항목 | 내용 |
|------|------|
| **캘리브레이션 절차** | **0~8 순서대로 각 1초씩 응시** → 오프셋/스케일 보정. (현재 HTML 1회 캘리 있으면 동일 개념 적용.) 사용자별 보정값 저장: [x] **예** (세션 또는 로컬 저장 권장). |
| **감도 파라미터** | **GRID_YAW_RANGE, GRID_PITCH_RANGE** (config_gaze.py, 현재 ±25° / ±20°). **반응 속도 vs 떨림**: 범위 넓음 → 반응 넓지만 떨림 노출; 범위 좁음 → 정확하지만 선택이 어려울 수 있음. 기본값 유지 후 테스트로 조정. |
| **UI 노출** | 감도 슬라이더 등 사용자 조절: [ ] 예 / [x] **아니오 (우선)** — 기본값으로 고정, 필요 시 설정 화면에서 추후 노출. |
