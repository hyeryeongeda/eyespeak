# 6~9분할 화면을 위한 캘리브레이션 설계

루게릭 환자용 안구 추적 서비스에서 **최소 6분할, 최대 9분할** 화면을 정교하게 쓰기 위한 캘리브레이션 구성 가이드입니다.

---

## 1. 목표

- **입력**: 시선 예측값 (모델/전처리 출력)  
  - 예: `(xNorm, yNorm)` ∈ [0,1]² 또는 스크린 픽셀 `(x, y)`
- **출력**: 6~9개 **이산 영역 인덱스** (어느 칸을 보고 있는지)
- **요구**: 경계 부근에서 오인식 최소화, 환자 피로 최소화(캘리 단계 짧게)

---

## 2. 분할 레이아웃

| 분할 수 | 그리드 | 용도 예시 |
|--------|--------|-----------|
| **6분할** | 2×3 또는 3×2 | 메인 4개 + 뒤로가기 + 빈칸, 또는 6개 선택지 |
| **9분할** | 3×3 | 이모지/키보드형 UI, 8방향+중앙(휴식) |

- **6분할**: `cols=2, rows=3` 또는 `cols=3, rows=2` → 영역 경계 5개(가로 1~2개, 세로 2~1개)
- **9분할**: `cols=3, rows=3` → 경계 4개(가로 2, 세로 2)

분할이 많을수록 **경계 정밀도**가 중요하므로, 9분할일 때는 캘리 포인트 수를 늘리는 것을 권장합니다.

---

## 3. 캘리브레이션 단계 (정교한 매핑)

### 3.1 캘리 포인트 배치

시선→화면 좌표 매핑을 학습하기 위해 **화면 위에 고정점**을 두고, 사용자가 그 점을 보는 동안 샘플을 수집합니다.

- **6분할 권장**: **9점 (3×3)**  
  - 화면을 3×3으로 나누어 각 칸 중심(또는 모서리+중앙)에 1점씩.  
  - 6분할은 경계가 적어 9점으로도 충분.
- **9분할 권장**: **9점 최소, 이상적으로 25점 (5×5)**  
  - 9분할은 칸이 작고 경계가 많으므로, 5×5 그리드로 **경계 근처**까지 보간 품질을 높이면 오인식이 줄어듦.  
  - 기존 `미디어파이프_이모지_9분할.html`의 25점 방식이 이에 해당.

포인트 좌표는 **화면 비율**로 두고, 실제 픽셀은 런타임에 계산하는 것이 좋습니다.

```text
9점 (3×3):   x = [0.15, 0.5, 0.85],  y = [0.15, 0.5, 0.85]
25점 (5×5):  x = [0.1, 0.3, 0.5, 0.7, 0.9],  y = 동일
```

- **수집 시간**: 점당 1.2~2.5초(고정 0.5초 + 수집 1.2초 등). 25점이면 약 40~50초.
- **더블 블링크 스킵**: 환자 피로를 줄이기 위해 “더블 블링크 시 다음 점으로”를 지원하면 좋음(현재 9분할 데모에 있음).

### 3.2 매핑 모델 (raw gaze → screen)

두 가지 방식을 조합할 수 있습니다.

| 방식 | 장점 | 단점 | 권장 |
|------|------|------|------|
| **2차 다항식** | 구현 간단, 9점으로 6계수 추정 가능 | 경계 밖에서 왜곡 가능 | 6분할, 9점 |
| **RBF (Gaussian)** | 캘리 점을 정확히 통과, 부드러운 보간 | 25점일 때 행렬 크기 증가 | 9분할, 25점 |

- **다항식**:  
  `screen_x = c0 + c1*x + c2*y + c3*x*y + c4*x² + c5*y²` (y도 동일 6계수).  
  `eye_mouse.js`의 `polyFeats` + `fitCalibration`이 이에 해당.
- **RBF**:  
  캘리 점에서 수집한 특징 벡터를 중심으로 Gaussian kernel로 보간.  
  `미디어파이프_이모지_9분할.html`의 `buildRBFWeights` + `predictGazeXY`가 이에 해당.

**권장 조합**

- **6분할**: 9점 + 2차 다항식.  
- **9분할**: 25점 + RBF (또는 9점 + 다항식으로 시작 후, 필요 시 25점+RBF로 업그레이드).

### 3.3 개인화(per-user) 저장

- 캘리 결과(계수 또는 RBF 가중치 + 중심)는 **사용자(환자) 단위**로 저장.  
- 보호자 모드에서 “캘리 다시하기”로 재수집 가능하게 두면, 자세/조명 변화에 대응하기 좋습니다.

## 4. 영역 할당 (screen → 6/9 인덱스)

스크린 좌표 `(sx, sy)`를 6 또는 9 개 영역 중 하나로 바꾸는 방법은 두 가지입니다.

### 4.1 그리드 경계 방식 (직관적)

- 화면을 `cols × rows`로 나누고, 각 칸의 픽셀 경계를 고정.
- `sx`, `sy`가 어느 사각형 안에 들어가는지로 인덱스 결정.

```text
col = floor(sx / (screenWidth / cols))
row = floor(sy / (screenHeight / rows))
idx = row * cols + col   (0 ~ N-1)
```

- **장점**: 구현 단순, “이 칸을 눌렀다”와 일치.  
- **단점**: 경계선 한 픽셀 오차로 인접 칸으로 넘어갈 수 있음 → **아래 히스테리시스/인접 완화**와 함께 쓰는 것을 권장.

### 4.2 최근접 중심(Voronoi) 방식 (권장)

- 각 영역의 **대표점**(예: 칸 중심) 좌표를 두고, `(sx, sy)`에서 **가장 가까운 대표점**의 인덱스를 선택.
- 경계는 두 중심의 수직 이등분선이 되므로, 작은 떨림에 덜 민감.
- 현재 9분할 데모의 `tileCenters2d` + `inertiaPickIdx`가 이와 유사합니다.

**6분할 예시 (2×3)**  
타일 중심을 2×3으로 두고, `argmin_i distance((sx,sy), center_i)` 로 `i` 선택.

**9분할**  
3×3 타일 중심 9개에 대해 동일.

- **인버티아(inertia)**:  
  “이전 프레임에서 선택된 영역”을 유지하다가, 다른 영역이 **일정 시간(예: 200~300ms) 연속으로 더 가까우면**만 전환.  
  `SWITCH_HOLD_MS`, `SWITCH_MARGIN` 같은 파라미터로 조절.  
  → 경계에서 시선이 흔들릴 때 오클릭을 줄여 **정교함**을 높입니다.

---

## 5. Dwell(고정 시간)과 결합

- “시선이 해당 영역에 **일정 시간(예: 0.5~1.5초)** 머물렀을 때만 선택”으로 두면, 순간 지나침으로 인한 오선택을 줄일 수 있습니다.
- 6~9분할 모두 **동일한 dwell 로직**을 쓰고, **영역 인덱스만** 6 또는 9로 바꾸면 됩니다.

---

## 6. 구현 체크리스트 (정교한 6~9분할)

1. **캘리 포인트**
   - [ ] 6분할: 9점 (3×3) 비율 고정
   - [ ] 9분할: 9점 또는 25점 (5×5) 선택 가능
   - [ ] 점 위치를 화면 비율로 정의해 해상도/창 크기 변경에 대응
2. **매핑**
   - [ ] 9점 → 2차 다항식 (polyFeats + lstsq)
   - [ ] 25점 → RBF (Gaussian, sigma 자동 추정)
   - [ ] 캘리 데이터(계수/가중치) per-user 저장/로드
3. **영역 할당**
   - [ ] 6분할: 2×3 또는 3×2 타일 중심 정의 → 최근접 중심 + inertia
   - [ ] 9분할: 3×3 타일 중심 → 최근접 중심 + inertia
   - [ ] (선택) 그리드 경계 방식으로 “실제 클릭 영역”과 일치 여부 검증
4. **안정화**
   - [ ] SWITCH_HOLD_MS, SWITCH_MARGIN (또는 동등 파라미터)로 전환 지연/마진 설정
   - [ ] Dwell 시간 설정 가능(보호자 모드 등)
5. **UX**
   - [ ] 더블 블링크로 캘리 “다음 점” 스킵
   - [ ] 캘리 진행률 표시 (예: 3/9, 12/25)

이 구성을 따르면 **최소 6분할, 최대 9분할** 화면을 정교하게 구현할 수 있습니다.

## 7. 공통 모듈 사용 (calibration_6_to_9.js)

`GazeCapture/MPIIGAZE/web_demo/calibration_6_to_9.js` 에서 다음을 사용할 수 있습니다.

| 함수/상수 | 설명 |
|-----------|------|
| `getCalibPoints(9)` / `getCalibPoints(25)` | 캘리 포인트 비율 배열 (화면 0~1) |
| `getCalibPointsPx(n, W, H)` | 픽셀 좌표로 변환 |
| `fitPolynomialCalibration(calibData)` | 9점 수집 데이터 → 다항식 계수 `{ cx, cy }` |
| `predictScreenPolynomial(xNorm, yNorm, cx, cy, W, H)` | (xNorm,yNorm) → 스크린 픽셀 |
| `getRegionIndex(sx, sy, layout, 'grid'\|'nearest', W, H)` | 스크린 좌표 → 영역 인덱스 |
| `getTileCentersPx(cols, rows, W, H)` | 타일 중심 픽셀 (nearest용) |
| `applyInertia(currentIdx, state, now, { holdMs, margin })` | 인덱스 전환 시 inertia 적용 |
| `LAYOUTS.split6_2x3` / `split6_3x2` / `split9` | cols/rows 프리셋 |

**6분할 예시 (2×3)**  
`layout = CalibrationRegion.LAYOUTS.split6_2x3` → `getRegionIndex(sx, sy, layout, 'nearest', W, H)`  
**9분할 예시**  
`layout = CalibrationRegion.LAYOUTS.split9` 동일.

## 8. 웹 데모 실행 방법

캘리브레이션과 6/9분할을 **브라우저에서 바로** 사용해 보려면 로컬 HTTP 서버로 `web_demo` 폴더를 서빙해야 합니다. (카메라 접근은 보안상 `file://`에서 불가합니다.)

**방법 1 — Python**
```bash
cd GazeCapture/MPIIGAZE/web_demo
python -m http.server 8080
```
브라우저에서 `http://localhost:8080/demo_6_to_9_split.html` 로 접속.

**방법 2 — Node (npx)**
```bash
cd GazeCapture/MPIIGAZE/web_demo
npx serve -p 8080
```
`http://localhost:8080/demo_6_to_9_split.html` 로 접속.

**데모 페이지**
- **demo_6_to_9_split.html** — 6분할/9분할 전환, 9점 캘리브레이션(다항식), MediaPipe 시선 → 영역 선택 + dwell
- **eye_mouse.html** — YOLO 눈/홍채 + 9점 캘리 → 시선 커서 (기존)
- **미디어파이프_이모지_9분할.html** — 25점 RBF 캘리, 9분할 이모지 키보드 (프로젝트 루트)
