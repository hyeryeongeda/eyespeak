# 2단계: 데이터 전략

> EYESPEAK 아이트래킹 개발 플랜 2단계 산출물. "어떤 데이터로, 어떤 레이블로 학습·검증할지" 한 문장으로 설명 가능한지 체크 후 3단계로 진행한다.

## 2-1. AI Hub(안구 움직임) 데이터 포맷 확인

> 먼저 **샘플(소량)** 만 확인. 500GB 전부 말고 샘플 폴더 경로를 아래처럼 실행하면 폴더 구조·파일 종류·메타데이터 후보를 출력한다.  
> `python scripts/inspect_aihub_format.py /path/to/aihub_eye/sample/`

| 항목 | 확인 결과 |
|------|-----------|
| **샘플 경로** | 서버: `~/yh_eyetracking_model/eye_tracking_sample` (또는 `/home/j-j14e205/yh_eyetracking_model/eye_tracking_sample`) |
| **폴더 구조** | `eye_tracking_sample/라벨링데이터/TL/G1/001,002/` → 각 참가자 아래 `30`, `50`, `VR`(거리·조건), 그 안에 XML |
| **파일 형식** | 레이블: **.xml**. 영상: (샘플 내 0개, 원본은 별도 경로 가능) · 이미지: (샘플 내 0개) |
| **메타데이터** | XML: `라벨링데이터/TL/G1/{참가자}/{30\|50\|VR}/NIA_EYE_G1_{참가자}_{조건}_{RGB\|IR\|DEPTH}.xml` |
| **레이블 유무** | [x] **있음** (시선/눈 관련 레이블, XML 내 필드 확인 권장) / [ ] 없음(영상만) |
| **레이블 형식** | 파일별 XML, 조건(30/50/VR)·모달리티(RGB/IR/DEPTH)별 파일. 단위·필드명은 XML 열어서 확인. |

## 2-2. 도메인 갭 정리

> 1단계 결정: **침대 시나리오, 카메라–얼굴 약 60cm(50~70cm), ruz UHD 2160 일반 웹캠**

| 갭 항목 | 데이터셋(AI Hub 등) | EYESPEAK 실제 환경 | 갭 축소 수단 |
|---------|---------------------|---------------------|--------------|
| **거리** | AI Hub: 30cm, 50cm, VR 고정 조건 | **약 60cm (50~70cm)** | 전처리·크롭/재수집/합성 |
| **각도** | (데이터셋 스펙 확인) | 침대 누움, 헤드 포즈 추후 측정 | 전처리·증강/재수집 |
| **해상도** | (원본 이미지/영상 경로 확인 후) | ruz UHD 2160 (4K) | 리사이즈·전처리 통일 |
| **조명** | (데이터셋 스펙 확인) | 침대실 실내 조명 | 정규화·전처리 |
| **기타** | RGB/IR/DEPTH 레이블 파일 분리 | 일반 RGB (IR 아님) | — |

## 2-4. 직접 수집 vs 기존만 활용

| 항목 | 결정 |
|------|------|
| **선택** | [ ] 기존 데이터만 활용 / [ ] 직접 수집 포함 / [x] **둘 다 (기존 + 소량 직접)** — 2-1 확인 후 최종 결정 |
| **직접 수집 시** | 카메라: [ ] IR / [x] **일반 웹캠 (ruz UHD 2160)** |
| **대상** | 침대 누운 포즈 유사(테스터), 1단계 거리·각도 준수 |

| **품 대비 효과** | AI Hub만 쓰면 거리·조명 갭 있음 → 소량이라도 실환경(60cm, 침대) 수집 시 검증·파인튜닝에 유리. |
