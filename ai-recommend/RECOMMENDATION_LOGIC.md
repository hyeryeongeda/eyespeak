# AI 추천 로직 상세 설명

`caregiver_server_db.py`의 추천 알고리즘을 단계별로 설명.

---

## 1. 데이터 소스

추천에 사용하는 데이터는 2가지:

| 데이터 | 출처 | 설명 | 예시 |
|---|---|---|---|
| **user_db** | 환자 개인 데이터 (expressions 테이블) | 환자가 과거에 사용한 표현들 | "물 좀 줘", "배고파", "손녀딸 보고 싶어" |
| **general_db** | 범용 말뭉치 (general_corpus 테이블) | 일반적인 대화 표현 ~1200개 | "응, 재밌었어", "별로야", "괜찮아" |

**설계 기준:** 환자 개인 데이터가 있으면 개인화 추천, 없으면(콜드스타트) 범용 말뭉치에서 추천.

## 2. 임베딩 모델

```
모델: paraphrase-multilingual-MiniLM-L12-v2
용도: 문장을 384차원 벡터로 변환 → 코사인 유사도로 의미적 유사성 측정
```

**선택 기준:**
- 한국어 포함 다국어 지원
- 경량 모델 (빠른 추론)
- 문장 간 의미 유사도 비교에 특화 (paraphrase 모델)

**캐시:** `embedding_cache`에 한 번 계산한 임베딩 저장 → 같은 문장 재요청 시 0ms

## 3. 추천 문장 검색 점수 계산

### 3-1. 기본 점수 (코사인 유사도 × 가중치)

```python
base_score = cosine_sim(질문 벡터, 표현 벡터) × weight
```

**코사인 유사도:** 보호자 질문과 환자 과거 표현의 의미적 유사도 (0~1)
- "밥 먹었어?" ↔ "배고파" → 높은 유사도
- "밥 먹었어?" ↔ "손녀딸 보고 싶어" → 낮은 유사도

**weight (사용 빈도 가중치):**

```python
weight = 1.0 + log(usageCount + 1)
```

| 사용 횟수 | weight | 의미 |
|---|---|---|
| 0회 | 1.0 | 기본값 |
| 1회 | 1.69 | 한 번 쓴 표현 |
| 5회 | 2.79 | 자주 쓰는 표현 |
| 10회 | 3.40 | 매우 자주 쓰는 표현 |

**설계 기준:** 자주 사용하는 표현일수록 높은 점수. log를 사용해서 극단적으로 많이 쓴 표현이 독점하지 않도록 완만하게 증가.

### 3-2. 시간대 부스트 (temporal_boost)

```python
def _calculate_temporal_boost(item, current_hour, current_weekday):
    if 마지막 사용 시간의 hour == 현재 hour:
        return 1.2   # 같은 시간대에 쓴 표현 → 20% 부스트
    if 마지막 사용 요일 == 현재 요일:
        return 1.1   # 같은 요일에 쓴 표현 → 10% 부스트
    return 1.0       # 기본
```

**설계 기준:** 환자가 특정 시간대/요일에 반복 사용하는 표현이 있을 수 있음.
- 아침에 "밥 먹었어" 자주 쓰면 → 아침에 더 높은 점수
- 월요일마다 "물리치료 힘들어" 쓰면 → 월요일에 더 높은 점수

### 3-3. 의도 부스트 (intent_boost)

```python
intent_boost = 1.5 if (intent_filter가 있고 표현의 카테고리에 포함) else 1.0
```

카테고리 기반 추천 시, 해당 의도(통증, 음식, 감정 등)에 맞는 표현에 50% 추가 점수.

### 3-4. 최종 점수

```
최종 점수 = base_score × temporal_boost × intent_boost
         = (코사인유사도 × 사용빈도가중치) × 시간대부스트 × 의도부스트
```

## 4. MMR (Maximal Marginal Relevance) — 다양성 확보

점수 순으로만 뽑으면 비슷한 문장끼리 몰리는 문제 발생.

```
예: "기분 좋아", "기분 괜찮아", "기분이 좋았어" → 다 비슷
```

**MMR 공식:**

```
MMR = λ × 관련성(질문↔후보) - (1-λ) × max(후보↔이미 선택된 문장 유사도)
```

- **λ = 0.7:** 관련성 70%, 다양성 30%
- 첫 번째 문장은 가장 관련성 높은 것 선택
- 두 번째부터는 관련성은 높되, 이미 선택된 문장과는 다른 것 선택

**결과:** "기분 좋아", "좀 힘들어", "배고파" → 감정/주제 다양

**설계 기준:** λ=0.7은 관련성을 유지하면서도 적당한 다양성 확보. λ가 낮으면 관련 없는 문장이 나올 수 있고, 높으면 다양성이 떨어짐.

## 5. 혼합 검색 (user_db + general_db)

```python
def _search_sentences_mixed(question, user_db, k_total=6):
    if len(user_db) == 0:  # 콜드스타트
        return _search_general(question, k=k_total)

    k_user = (k_total + 1) // 2     # 환자 데이터에서 4개

```

**비율:** 환자 데이터 : 범용 데이터 = 약 2:1

**설계 기준:**
- 환자 개인 표현이 더 중요 (개인화)
- 범용 말뭉치로 다양성 보완
- 콜드스타트(신규 환자)면 범용 데이터만 사용

## 6. LLM 후처리 (_refine_recommend)

임베딩 검색으로 찾은 후보 6개를 LLM에 넘겨서 자연스러운 문장 3개로 정제.

```
입력: 후보 6개 ["물 좀 줘", "목 말라", "갈증나", "배고파", "좋아", "고마워"]
     + 보호자 질문 "오늘 기분이 어때?"

LLM 지시: "반말 구어체, 15자 이내, 3개 생성"

출력: ["기분 좋아!", "좀 힘들어.", "괜찮아"]
```

**LLM 모델:** gpt-4.1-nano (1 credit, 빠르고 저렴)
**temperature:** 0.7 (적당한 다양성)
**max_tokens:** 60 (15자 × 3개면 충분)

**설계 기준:**
- 임베딩 검색은 의미적으로 비슷한 표현을 찾지만, 문장이 부자연스러울 수 있음
- LLM이 보호자 질문 시제/맥락에 맞게 자연스러운 답변으로 다듬어줌
- ALS 환자 특성: 반말 구어체, 짧은 문장 (시선 입력이라 길면 안 됨)

**캐시:** 같은 질문+후보 조합이면 LLM 재호출 없이 캐시 반환 (0.01ms)

## 7. 단어 추천 로직 (_search_words)

단어 조합 키보드용. 주어 → 목적어 → 서술어 순서로 추천.

### 7-1. 후보 추출 (3단계)

```
1단계: 임베딩 유사 표현에서 키워드 추출 (_extract_keywords_from_similar)
  → 질문과 비슷한 과거 표현들의 키워드를 빈도순으로 추출

2단계: 형태소 분석으로 품사 추출 (_extract_words_by_pos)
  → KoNLPy Okt로 명사/동사/형용사 분리

3단계: LLM 필터링 (_llm_filter_words)
  → 부사/어미/조사 제거, 해당 품사만 남김
```

### 7-2. 점수 계산

```python
def score(word):
    sim = cosine_sim(질문 벡터, 단어 벡터)
    norm_freq = 사용빈도 / 최대빈도    # 0~1 정규화
    base = sim × (1.0 + 0.5 × norm_freq)
    context_boost = 1.0 + 0.4 × max(이전 선택 단어와의 유사도)
    return base × context_boost
```

**context_boost (맥락 부스트):**
- 이전 단계에서 선택한 단어와 의미적으로 관련 있는 단어에 가산점
- 주어로 "나"를 선택하면 → 목적어에서 "밥", "물" 같은 관련 단어 우선
- α = 0.4: 맥락 반영 40%

**설계 기준:** 단어 조합이 문맥상 자연스럽도록 이전 선택을 참고.

## 8. 문장 분류 (_classify_sentence_for_storage)

환자가 보낸 문장의 감정(sentiment)과 의도(intent)를 분류.

### 8-1. 키워드 기반 분류 (1차)

```python
# 감정 분류
_POSITIVE_KEYWORDS = {"좋", "행복", "맛있", "기쁘", "신나", "편하", "괜찮"}
_NEGATIVE_KEYWORDS = {"싫", "아파", "슬프", "화", "힘들", "불편", "우울"}

# 의도 분류
_INTENT_KEYWORDS = {
    "통증": {"아파", "쑤시", "뻐근", "저리", "불편"},
    "욕구": {"먹고 싶", "마시고 싶", "줘", "보고 싶"},
    "음식": {"밥", "물", "약", "배고파", "목말라"},
    "요청": {"도와", "해줘", "바꿔", "켜줘"},
    "감정": {"좋아", "싫어", "슬프", "행복", "화나"},

```

**설계 기준:** ALS 환자가 자주 쓰는 표현 패턴 기반. 빠르고 정확한 1차 필터.

### 8-2. LLM 분류 (2차 — 키워드로 못 잡을 때)

```python
if sentiment == "중립" and intent == "기타":
    # 키워드로 분류 실패 → LLM에 위임
    sentiment, intent = _classify_sentence_llm(text)
```

키워드에 없는 새로운 표현이면 LLM(gpt-4.1-nano)이 분류.

**설계 기준:** 키워드 기반이 빠르지만 커버리지 한계 → LLM fallback으로 보완.

## 9. 키워드 자동 추출 (_auto_generate_keywords)

### KoNLPy 사용 가능한 경우

```python
okt.pos(text, norm=True)
→ 명사(Noun) + 동사/형용사(Verb/Adjective) 추출
→ 불용어(_NOUN_STOPWORDS) 제거
→ 동사는 "다" 붙여서 원형으로 저장
```

**예:** "물 좀 줘" → ["물", "주다"]

### KoNLPy 없는 경우

```python
text.split()으로 단어 분리 → 2글자 이상만
```

**설계 기준:** 키워드는 추천 검색 시 표현을 찾는 데 사용. 정확한 형태소 분석이 되면 좋지만, 없어도 기본 동작.

## 10. 카테고리 생성 (_generate_categories)

보호자 질문에 맞는 답변 카테고리를 LLM이 생성.

```
입력: "오늘 기분이 어때?"
     + 환자 키워드: ["기분", "좋다", "힘들다", ...]
     + 환자 표현: ["기분 좋아", "좀 힘들어", ...]

LLM 판단:
  닫힌 질문 → [좋아, 싫어, 그저그래] 같은 고정 선택지
  개방형 질문 → 키워드 참고한 구체적 선택지

출력: { categories: ["좋아", "별로", "그저그래"],
        sentimentMap: {"좋아": "긍정", ...},
        intentMap: {"좋아": "감정", ...} }
```

**캐시:** 같은 질문이면 캐시 반환 (0.02ms)

**설계 기준:** ALS 환자는 시선 입력이라 선택지가 적고 명확해야 함. 닫힌 질문은 2~3개, 개방형은 3~4개.

## 11. 전체 추천 흐름 요약

```
보호자: "밥 먹었어?"
    ↓
1. 임베딩 검색: 질문과 유사한 환자 과거 표현 6개 찾기
   → 코사인유사도 × 사용빈도가중치 × 시간대부스트 × 의도부스트
    ↓
2. MMR: 6개 중 다양한 후보 선택
   → 관련성 70% + 다양성 30%
    ↓
3. LLM 후처리: 후보를 참고해서 자연스러운 답변 3개 생성
   → 반말 구어체, 15자 이내, 시제 맞춤
    ↓
환자 화면: ["응 먹었어", "아직 안 먹었어", "배고파서 먹고 싶어"]
```
