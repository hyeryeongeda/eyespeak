# 추천 로직 트러블슈팅 기록

## TS-001: "언니는 잘 지내?" — 페르소나에 안 맞는 문장 추천

**증상:** "오늘 기분이 어때?" 질문에 "언니는 잘 지내?"가 추천됨. 67세 남성 환자가 "언니"라고 할 리 없음.

**원인:**
- general_corpus(범용 말뭉치)에 젊은 여성 말투의 인터넷 대화체 ~2900개가 포함
- "언니는 잘 가고 있어?", "배민으로 시켜줄까" 등 부적절한 문장이 추천 후보로 올라옴

**해결:**
- general_corpus를 페르소나에 맞는 ~400개로 교체 (인터넷체 전부 제거)
- 67세 남성 ALS 환자 말투에 맞는 차분한 문장만 포함

---

## TS-002: "맛있엉!", "진짜 맛있엉!" — 환자 말투 안 맞음

**증상:** "오렌지 주스 맛이 어때?" 질문에 "맛있엉!", "진짜 맛있엉!" 같은 귀여운 말투 추천.

**원인:**
- general_corpus에 "~엉", "~징" 같은 인터넷 대화체 포함
- LLM 프롬프트에 환자 페르소나(67세 남성) 정보 없음

**해결:**
- general_corpus에서 인터넷 용어, 귀여운 말투 전부 제거
- LLM system prompt에 `PATIENT_PERSONA` 추가: "67세 남성 ALS환자. 차분하고 담백한 말투."

---

## TS-003: "배민으로 시켜줄까" — 완전히 엉뚱한 추천

**증상:** 보호자가 "주스 줄게" 했는데 추천 중 하나가 "배민으로 시켜줄까"

**원인:**
- general_corpus에 일상 대화체("배민으로 시켜줄까", "카페 갈래?" 등) 포함
- MMR 다양성(λ=0.7)이 너무 높아서 관련 없는 문장까지 끌려옴
- general_corpus 비중(user:general = 4:2)이 너무 높음

**해결:**
- general_corpus 전면 교체 (ALS 환자 맥락에 맞는 문장만)
- MMR λ=0.7 → 0.85 (관련성 85%, 다양성 15%)
- user:general 비중 4:2 → 5:1

---

## TS-004: "트로트 듣고 싶어", "왼쪽 어깨 또 저려" — 질문과 관련 없는 추천

**증상:** "오렌지 주스 줄까?" 질문에 "트로트 듣고 싶어", "왼쪽 어깨 또 저려" 추천

**원인:**
- `/recommend/replies`에서 임베딩 검색 시 "오렌지 주스"와 관련 없는 자주 쓴 표현이 높은 점수
- weight(사용빈도 가중치)가 높은 표현이 관련성 없이 상위에 올라옴

**해결:**
- MMR λ 올려서 관련성 높은 것 우선
- general_corpus 비중 줄여서 user 데이터 위주로

---

## TS-005: 카테고리에 "음식", "욕구", "일상" — 추상적인 카테고리

**증상:** "요즘 좋아하는 음식 뭐야?"에 카테고리가 ["음식", "욕구", "일상"] — 환자가 선택할 수 없는 추상적인 단어

**원래 나와야 하는 것:** ["계란죽", "오렌지 주스", "김치찌개", "잘 모르겠어"]

**원인:**
- 프롬프트 축소 과정에서 카테고리 생성 규칙의 예시가 삭제됨
- LLM이 구체적 선택지 대신 추상적 분류명을 반환

**해결:**
- 프롬프트에 구체적 예시 추가:
  - "뭐 먹고 싶어?" → ["계란죽", "국밥", "주스", "잘 모르겠어"]
  - "어디 아파?" → ["어깨", "다리", "허리", "잘 모르겠어"]
- "음식, 욕구, 일상 같은 추상적인 단어 금지" 명시

## TS-006: 카테고리 생성 JSON 파싱 실패 → fallback

**증상:** 카테고리가 항상 ["좋아", "싫어", "그저그래"]로 나옴 (fallback 기본값)

**원인:**
- gpt-4.1-nano 모델이 복잡한 JSON(categories + sentimentMap + intentMap) 생성 시 형식 오류
- `Extra data: line 1 column 197` — JSON 뒤에 불필요한 텍스트 붙임
- nano는 단순 텍스트 생성에는 좋지만 구조화된 JSON에 약함

**해결:**
- 카테고리 생성만 `gpt-4o-mini`로 복원 (나머지 함수는 nano 유지)
- retry 3회 복원
- max_tokens 200 복원
- JSON 뒤 불필요한 텍스트 자동 제거 로직 추가 (중괄호 매칭)

## TS-007: 프롬프트 축소로 추천 품질 저하

**증상:** 전반적으로 추천 품질이 이전보다 떨어짐

**원인:**
- 성능 최적화 과정에서 프롬프트를 ~60% 축소함
- 핵심 지시사항(시제 맞춤, 다양성 규칙, 예시 등)이 삭제됨
- LLM이 맥락을 충분히 이해하지 못하고 엉뚱한 답변 생성

**해결:**
- 원본 caregiver_server.py의 상세 프롬프트로 복원
- 페르소나 정보만 system prompt에 추가
- 프롬프트 축소는 품질과 트레이드오프 — 무작정 줄이면 안 됨

**교훈:** 프롬프트 최적화 시 토큰 수 줄이기보다 **모델 변경**이 더 효과적. 프롬프트는 품질에 직접 영향.

## TS-008: MMR λ=0.7 너무 높은 다양성

**증상:** 관련 없는 문장이 다양성 확보 명목으로 추천에 포함

**원인:**
- MMR λ=0.7은 관련성 70%, 다양성 30%
- 30%가 너무 커서 질문과 관련 없는 문장도 "다양성"으로 선택됨

**해결:**
- λ=0.7 → 0.85 (관련성 85%, 다양성 15%)
- 관련성 우선, 다양성은 최소한만

---

## TS-009: data.sql `INSERT IGNORE`로 데이터 안 들어감

**증상:** data.sql 실행했는데 users, patient, matching 등 테이블이 비어있음

**원인:**
- `is_agree` 컬럼이 `bit(1)` 타입인데 `true`로 INSERT → MySQL이 조용히 실패
- `INSERT IGNORE`라서 에러 메시지 없이 스킵됨

**해결:**
- `true` → `1`로 변경 (bit(1) 타입에 맞게)
- 또는 수동으로 users 먼저 INSERT 후 data.sql 실행

---

## TS-010: data.sql 자동 실행 시 테이블 없음 에러

**증상:** BE 서버 시작 시 `Table 'eyespeak.expressions' doesn't exist`

**원인:**
- `ddl-auto: create`와 data.sql 실행 순서가 안 맞음
- `defer-datasource-initialization: true` 설정이 간헐적으로 안 먹힘

**해결:**
- `application-local.yml`에서 `sql.init.mode: never`로 변경
- BE 서버 실행 (테이블만 생성) → data.sql 수동 실행
- `docker exec -i eyespeak-db-local mysql -u root -proot1234 eyespeak < data.sql`
