# 📝 Eye-tracking Model Test Report: Custom CNN Gaze Model

**작성일**: 2026-03-05
**테스트 담당자**: KSH

---

### 1. 테스트 개요
* **모델명**: Custom GazeCNN (PyTorch + MediaPipe + Calibration)
* **선정 이유**: AI Hub 안구 움직임 데이터셋(28,080쌍)을 활용한 End-to-End 시선 추적 모델 직접 구현. 기존 오픈소스 모델 대비 커스터마이징 가능성이 높고, 추후 IR 카메라 연동 및 파인튜닝이 용이함.
* **주요 기능**:
    * 실시간 시선 좌표(x, y) 추적 및 마우스 커서 이동
    * MediaPipe를 통한 눈 영역 크롭 후 CNN 모델 추론
    * 4포인트 캘리브레이션으로 개인화 보정
    * 칼만 필터 기반 떨림 제거
    * Dwell(응시) 방식 버튼 선택 (1.5초 응시 시 선택)

### 3. 성능 평가

#### 3.1 정확도 (Accuracy)
* **시선 추적 정밀도**:
    * 화면 중앙부는 어느 정도 추적되나 가장자리 오차 큼
    * 캘리브레이션 후에도 의도한 버튼 정확히 가리키기 어려움
* **오차 범위**: 약 24px (검증손실 0.0123 기준, 1920x1080)
* **보정(Calibration) 필요성**: 4포인트 캘리브레이션 필수. 포인트 수가 적어 보정 정밀도 한계 있음.

#### 3.2 응답 속도 (Latency & FPS)
* **평균 FPS**: `[ 25~30 ]` FPS (GPU 사용 시 실시간 추론 가능)
* **딜레이**: 칼만 필터 적용으로 약 0.1~0.2초 지연 체감
* **리소스 소모**: GPU 사용으로 CPU 부담 낮음

#### 3.3 안정성 (Stability)
| 구분 | 테스트 결과 | 비고 |
| :--- | :--- | :--- |
| **안경 착용** | ⚠️ 오차 증가 | 반사광으로 눈 인식 불안정 |
| **고개 움직임** | ❌ 인식 불가 | 고개 움직이면 좌표 크게 튐 |
| **주변 밝기** | ⚠️ 오차 증가 | 어두운 환경에서 눈 크롭 실패 |

---

### 4. 결론 및 종합 의견

#### 💡 서비스 도입 적합성
* **적합 여부**: 현재 단계에서는 부적합. 추가 개선 후 부분 도입 가능.
* **이유**: 검증손실 기준 정확도는 나쁘지 않으나, 실제 웹캠 환경에서 학습 데이터(눈 클로즈업)와 입력 데이터(얼굴 전체) 간 도메인 갭이 발생해 실사용 정확도가 낮음. Dwell 방식 버튼 선택 자체는 구현됐으나 시선이 의도한 버튼을 정확히 가리키기 어려운 상태.

#### ⚠️ 도입 시 고려사항
* 학습 데이터와 실제 입력 환경 일치 필요 → IR 카메라 도입 또는 웹캠 환경 데이터 추가 수집
* 훈련 데이터(TS) 전체 학습 필요 (현재 검증 데이터만 사용, 약 10배 확장 가능)
* 캘리브레이션 포인트 확대 (4포인트 → 9포인트 이상) 시 정확도 향상 기대
* IR 카메라(OV9281, 약 3~5만원) 도입 시 코드 한 줄 변경으로 바로 적용 가능
