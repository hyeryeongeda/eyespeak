# EYESPEAK 시선 추정 — 현재 모델 요약 (LLM용)

> 새 아이디어·기획·개선안을 만들 때 참고할 수 있도록, 기술 스택·한계·제약·가능 레버를 한 문서로 정리한 요약본.  
> **메인 코드베이스**: `eyespeak-gaze` (경로는 해당 프로젝트 기준).

---

## 1. 프로젝트 컨텍스트

- **서비스**: EYESPEAK — 루게릭(ALS) 환자를 위한 **시선 기반 AI 의사소통 플랫폼**
- **목표**: 고가 장비 없이 **웹캠(또는 적외선 카메라)** 로 시선을 감지해, 화면 UI(버튼/그리드)를 **시선으로 선택**하여 의사를 전달
- **타겟**: 환자(침대/휠체어)·간병인(배우자 등). **경제적 접근성**과 **즉각 반응·LLM 대기 시간**을 함께 고려해야 함
- **MVP 기능**: SOS 긴급 호출, 필수/자유 의사소통(문장 선택), 채팅+AI 추천, 통증/불편 표현(통증 지도)

---

## 2. 현재 기술 스택 (한 줄 요약)

**BGR 프레임 → (선택) 전처리 → YOLOv8-pose 눈 검출·크롭 → GazeNet(눈만 입력) → yaw/pitch(도) → 9그리드(0~8) 매핑 → Flask API·웹 9그리드 UI**

| 구성요소 | 역할 | 입출력 |
|----------|------|--------|
| **eye_detector.py** | YOLOv8-pose COCO 키포인트(왼/오른쪽 눈)로 눈 영역 검출·크롭 | BGR 프레임 → (left_eye, right_eye) RGB 128×128 |
| **model.py (GazeNet)** | 눈 이미지 → 시선 각도 회귀 (appearance 기반 CNN) | 224×224 RGB → (yaw_rad, pitch_rad) |
| **preprocess.py** | CLAHE·양방향 필터 (선택) | 프레임/눈 크롭 보정 |
| **config_gaze.py** | 입출력·그리드 범위·체크포인트·전처리 플래그 | YAW ±25°, PITCH ±20° → 3×3 그리드 |
| **app_gaze_web.py** | Flask 서버: 정적 HTML 서빙, POST /api/gaze | base64 이미지 → `{ left: {yaw, pitch}, right: {...} }` |
| **시선_예시/gaze_server_9grid.html** | 웹캠 캡처 → 서버 전송 → 하이라이트·1.5초 응시 시 선택 확정 | - |

- **학습 데이터 (GazeNet)**: MPIIGaze 스타일. 체크포인트: `checkpoints/best.pt`
- **백엔드 전환**: `GAZE_BACKEND`(기본 `gazenet`). L2CS-Net 등은 아직 미연동, 연동 시 여기서 스위치 예정

---

## 3. 핵심 한계 (실사용에서 실패하는 이유)

- **GazeNet은 눈 이미지만 입력**하는 appearance 기반이라, **눈만 움직일 때** yaw/pitch 변화가 작고 **고개를 돌릴 때**만 크게 반응함. → 캘리브레이션을 "눈만 움직이는" 조건으로 해도, 실제 사용 시 **시선보다 고개 방향에 더 맞춰짐**
- **데이터–환경 괴리**: 학습 데이터(MPIIGaze 등)는 **전용 카메라·고정 거리·고정 포즈**로 수집된 반면, 실사용은 **일반/IR 웹캠·거리·각도·조명 변동** → 도메인 갭 큼
- **RGB 웹캠 한계**: 조명·반사 영향. 전문가 의견으로 **적외선 카메라**(노트북 직결 선호)가 빛/반사 이슈 완화에 유리
- **실시간 지연**: 파이프라인·네트워크 지연 존재. "즉각 반응"과 "LLM 생성 시간"을 함께 설계해야 함
- **테스트 이력**: MediaPipe는 가벼우나 성능 한계, **YOLO·L2CS-Net**은 오프라인 정확도는 나왔으나 **웹캠 실환경에서 시선 추적이 기대만큼 동작하지 않음** → 위 요인들이 복합적으로 작용한 것으로 추정

---

## 4. 설계·전문가 반영 사항

- **데이터가 가장 중요**: 실제 환자 환경에 가까운 데이터가 있어야 도메인 갭을 줄일 수 있음. 직접 수집 시 품이 크므로, **기존 공공 데이터(AI Hub 등) 포맷 확인·소량 실환경 데이터** 조합을 권장
- **데이터량 가이드**: 클래스당 최소 100, 이상적 1000. 16방향이면 1,600장 이상 등
- **적외선 카메라**: 조명·반사 완화에 유리, 가능하면 노트북에 직접 연결하는 방식 권장
- **UI로 오차 흡수**: **버튼/그리드 크기를 키워** 추적 오차 범위 안에서도 선택이 가능하도록. 필요 시 9→6 그리드 등
- **전처리**: OpenCV(CLAHE 등) 활용. 학습·추론 동일 파이프라인 적용
- **확정 방식**: "N초 응시 시 선택"으로 오선택 감소. SOS는 즉시, 일반 선택은 1~2초 유지 등 **기능별 차등** 설계 가능

---

## 5. 보유 데이터·활용 방향

- **안구 움직임 영상 데이터** (AI Hub 등, 약 547GB): 거리별·VR 내부 안구 움직임 영상. 얼굴 재구축·VR 시점·게임/애니 등 목적
- **레이블 있음** → GazeNet·L2CS-Net 등 **학습/파인튜닝**에 바로 활용 가능. 얼굴/눈 크롭 + 레이블만 현재 파이프라인에 맞추면 됨
- **영상만 있음** → (1) pretrain된 **얼굴+눈 모델**(L2CS-Net, ETH-XGaze 등)로 **추론만** 하거나, (2) **자기 지도/준지도**로 레이블 생성 후 학습·파인튜닝
- 데이터 포맷(폴더 구조, 메타, 파일명/확장자)이 정해지면 "eyespeak-gaze 구조에 어떻게 넣을지"를 구체 설계 가능

## 6. 새 아이디어·기획 시 쓸 수 있는 레버

| 레버 | 설명 | 예시 방향 |
|------|------|------------|
| **입력** | 얼굴+눈 vs 눈만, 해상도·프레임률, IR vs RGB | L2CS-Net·ETH-XGaze·Gaze360 등 얼굴+눈 모델 연동 |
| **데이터** | 실환경 vs 공공 데이터, 레이블 유무, 데이터량·다양성 | AI Hub 샘플 포맷 확인 → 파인튜닝 파이프라인, 소량 실환경 수집 |
| **모델** | appearance vs geometry, 백엔드 교체·앙상블 | GazeNet 유지 + 실환경 파인튜닝, 또는 L2CS-Net으로 전환 |
| **전처리** | CLAHE·노이즈 제거·정규화·도메인 맞춤 | 조명/거리 보정, IR 전용 정규화 |
| **UI/UX** | 그리드 수·버튼 크기·캘리브레이션·확정 시간 | 9→6 그리드, SOS 즉시/문장 1.5초, 감도 슬라이더 |
| **하드웨어** | 일반 웹캠 vs IR, 거리·각도 스펙 고정 | 1단계 하드웨어 결정서에 따라 타깃 환경 명시 |
| **지연·리소스** | FPS·엔드투엔드 지연, 경량화·양자화 | 경량 모델·서버/엣지 배치, "즉시 vs 유지" 기능별 분리 |
