### 1-3. 배포 시 특이사항

#### Prod 배포 방식: Blue/Green 무중단 배포

Jenkins가 `release` 브랜치 push 감지 시 자동 실행됩니다.

```
1. 현재 활성 서버 확인 (Blue or Green)
2. 비활성 서버에 새 버전 배포 (Docker 빌드 + 컨테이너 교체)
3. 헬스체크 (최대 90초, /api/v1/actuator/health → {"status":"UP"})
4. Nginx 트래픽 전환 (scripts/switch-upstream.sh)
5. Smoke Test (외부 HTTPS 접근 확인)
6. 실패 시 → 자동 롤백 (이전 서버로 트래픽 복귀) + Mattermost 알림
```

#### Prod 서버 시작 순서 (EC2)

```bash
# 1단계: 데이터 서비스 (네트워크 생성 필수)
make data-prod-up       # MySQL + Redis 시작, prod-net 네트워크 생성

# 2단계: Nginx 리버스 프록시
make infra-up           # Nginx 시작 (SSL, 라우팅)

# 3단계: 앱 배포 (Jenkins 자동 또는 수동)
make prod-app-up        # 백엔드 Blue/Green + 프론트엔드 Blue/Green

# 4단계: Eye Tracking (EC2 호스트에서 직접 실행)
sudo iptables -I INPUT -p tcp --dport 5000 -j ACCEPT
cd ~/eyespeak/ai-eyetracking
source venv/bin/activate
nohup python app_gaze_web.py > eyetracking.log 2>&1 &
```

#### RunPod GPU 서버 시작 (TTS + 추천)

```bash
# pip 패키지 설치 (Pod 재시작 시 매번 필요)
pip install --ignore-installed blinker
pip install -r /workspace/S14P21E205/ai-tts/requirements.txt
pip install "transformers<=4.40.0"
pip install -r /workspace/S14P21E205/ai-recommend/requirements.txt
pip install sentence-transformers "optimum[onnxruntime]" onnx

# TTS 서버 (포트 8000, GPU 사용)
cd /workspace/S14P21E205/ai-tts
nohup uvicorn tts_server:app --host 0.0.0.0 --port 8000 > /workspace/tts.log 2>&1 &

# Prod 추천 서버 (포트 5004)
cd /workspace/S14P21E205/ai-recommend
BE_API_URL=https://j14e205.p.ssafy.io/api/v1 GMS_KEY=<키값> nohup python caregiver_server_db_prod.py > nohup_prod.out 2>&1 &
```

#### 배포 시 주의사항

| 항목 | 내용 |
|------|------|
| EC2 재시작 후 | `sudo iptables -I INPUT -p tcp --dport 5000 -j ACCEPT` (Eye Tracking 방화벽 열기) |
| EC2 재시작 후 | `docker exec -u root jenkins chmod 666 /var/run/docker.sock` (Jenkins Docker 권한) |
| Prod 배포 전 | `make data-prod-up` 으로 Prod DB/Redis 먼저 시작 |
| RunPod Pod 설정 변경 시 | 시스템 pip 패키지 초기화됨 → pip install 재실행 필요 |
| Docker 빌드 캐시 에러 시 | `docker builder prune -f` 실행 |
| TTS transformers | 반드시 `<=4.40.0`으로 고정 (최신 버전은 호환 안 됨) |
| Blue/Green 수동 전환 | `make switch-blue` 또는 `make switch-green` |
| FCM 키 | Jenkins Credential에 Secret File로 등록, Jenkinsfile에서 빌드 시 자동 복사 |

## 2. 프로젝트에서 사용하는 외부 서비스 정리 문서

| 서비스 | 용도 | 가입/발급 방법 | 필요한 키/정보 | 프로젝트 내 사용 위치 |

| **AWS S3** | 보호자 TTS 음성 파일 저장 | AWS Console → IAM 사용자 생성 → S3 버킷 생성 | `AWS_ACCESS_KEY`, `AWS_SECRET_KEY`, `AWS_S3_BUCKET`, `AWS_REGION` | Jenkins Credential `env-backend-prod` 내 포함 |
| **Firebase (FCM)** | 보호자 앱 푸시 알림 (호출/채팅) | Firebase Console → 프로젝트 생성 → 프로젝트 설정 → 서비스 계정 → 새 비공개 키 생성 | `firebase-service-account.json` (서비스 계정 키 파일) | Jenkins Credential `fcm-secret-key` (Secret File) |

## 3. DB 덤프 파일

### 덤프 생성 방법

```bash
# Prod DB 덤프
docker exec eyespeak-db-prod mysqldump -u root -p<비밀번호> eyespeak \
  --default-character-set=utf8mb4 \
  --single-transaction \
  --routines \
  --triggers \
  > eyespeak_dump_prod.sql

# Dev DB 덤프
docker exec eyespeak-db-dev mysqldump -u root -p<비밀번호> eyespeak \
  --default-character-set=utf8mb4 \
  --single-transaction \
  > eyespeak_dump_dev.sql
```

### 덤프 복원 방법

```bash
docker exec -i eyespeak-db-prod mysql -u root -p<비밀번호> eyespeak < eyespeak_dump_prod.sql
```

#### category + phrase

- 시드 데이터: 일상 대화, 통증 표현, 감정 표현 등 사전 정의 문구
