### 1-3. 배포 시 특이사항

#### Prod 배포 방식: Blue/Green 무중단 배포

Jenkins가 `release` 브랜치 push 감지 시 자동 실행됩니다.

```
1. 현재 활성 서버 확인 (Blue or Green)
2. 비활성 서버에 새 버전 배포 (Docker 빌드 + 컨테이너 교체)
3. 헬스체크 (최대 90초, /api/v1/actuator/health → {"status":"UP"})
4. Nginx 트래픽 전환 (scripts/switch-upstream.sh)
5. Smoke Test (외부 HTTPS 접근 확인)
6. 실패 시 → 자동 롤백 (이전 서버로 트래픽 복귀) + Mattermost 알림
```

#### Prod 서버 시작 순서 (EC2)

```bash
# 1단계: 데이터 서비스 (네트워크 생성 필수)
make data-prod-up       # MySQL + Redis 시작, prod-net 네트워크 생성

# 2단계: Nginx 리버스 프록시
make infra-up           # Nginx 시작 (SSL, 라우팅)

# 3단계: 앱 배포 (Jenkins 자동 또는 수동)
make prod-app-up        # 백엔드 Blue/Green + 프론트엔드 Blue/Green

# 4단계: Eye Tracking (EC2 호스트에서 직접 실행)
sudo iptables -I INPUT -p tcp --dport 5000 -j ACCEPT
cd ~/eyespeak/ai-eyetracking
source venv/bin/activate
nohup python app_gaze_web.py > eyetracking.log 2>&1 &
```

#### RunPod GPU 서버 시작 (TTS + 추천)

```bash
# pip 패키지 설치 (Pod 재시작 시 매번 필요)
pip install --ignore-installed blinker
pip install -r /workspace/S14P21E205/ai-tts/requirements.txt
pip install "transformers<=4.40.0"
pip install -r /workspace/S14P21E205/ai-recommend/requirements.txt
pip install sentence-transformers "optimum[onnxruntime]" onnx

# TTS 서버 (포트 8000, GPU 사용)
cd /workspace/S14P21E205/ai-tts
nohup uvicorn tts_server:app --host 0.0.0.0 --port 8000 > /workspace/tts.log 2>&1 &

# Prod 추천 서버 (포트 5004)
cd /workspace/S14P21E205/ai-recommend
BE_API_URL=https://j14e205.p.ssafy.io/api/v1 GMS_KEY=<키값> nohup python caregiver_server_db_prod.py > nohup_prod.out 2>&1 &
```

#### 배포 시 주의사항

| 항목 | 내용 |
|------|------|
| EC2 재시작 후 | `sudo iptables -I INPUT -p tcp --dport 5000 -j ACCEPT` (Eye Tracking 방화벽 열기) |
| EC2 재시작 후 | `docker exec -u root jenkins chmod 666 /var/run/docker.sock` (Jenkins Docker 권한) |
| Prod 배포 전 | `make data-prod-up` 으로 Prod DB/Redis 먼저 시작 |
| RunPod Pod 설정 변경 시 | 시스템 pip 패키지 초기화됨 → pip install 재실행 필요 |
| Docker 빌드 캐시 에러 시 | `docker builder prune -f` 실행 |
| TTS transformers | 반드시 `<=4.40.0`으로 고정 (최신 버전은 호환 안 됨) |
| Blue/Green 수동 전환 | `make switch-blue` 또는 `make switch-green` |
| FCM 키 | Jenkins Credential에 Secret File로 등록, Jenkinsfile에서 빌드 시 자동 복사 |

## 2. 프로젝트에서 사용하는 외부 서비스 정리 문서

| 서비스 | 용도 | 가입/발급 방법 | 필요한 키/정보 | 프로젝트 내 사용 위치 |

| **AWS S3** | 보호자 TTS 음성 파일 저장 | AWS Console → IAM 사용자 생성 → S3 버킷 생성 | `AWS_ACCESS_KEY`, `AWS_SECRET_KEY`, `AWS_S3_BUCKET`, `AWS_REGION` | Jenkins Credential `env-backend-prod` 내 포함 |
| **Firebase (FCM)** | 보호자 앱 푸시 알림 (호출/채팅) | Firebase Console → 프로젝트 생성 → 프로젝트 설정 → 서비스 계정 → 새 비공개 키 생성 | `firebase-service-account.json` (서비스 계정 키 파일) | Jenkins Credential `fcm-secret-key` (Secret File) |

## 4. 시연 시나리오

### MOVE_P_001 — 여가 중 보호자 채팅 수신

> **진입 조건:** 환자가 유튜브 시청 중, 보호자가 채팅 전송

| 단계 | 화면 | 실행 동작 | 상세 설명 |
|------|------|-----------|-----------|
| 1 | **보호자 앱 — 채팅 화면** | 보호자가 채팅 입력창에 "오렌지 주스 마실래?" 입력 후 전송 버튼 클릭 | 메시지가 백엔드(`POST /api/v1/messages`)로 전송되고, WebSocket(STOMP)을 통해 환자 앱에 실시간 전달됨. 동시에 FCM 푸시 알림이 환자 디바이스로 발송됨 |
| 2 | **환자 앱 — 여가(유튜브) 화면** | 유튜브 영상 시청 중 화면 상단에 팝업 표시 | 팝업 내용: **"오렌지 주스 마실래? — 대화창으로 이동하시겠습니까?"** 환자의 시선 선택을 기다림 |
| 3-A | **환자 앱 — 팝업 [예] 선택** | 환자가 시선으로 [예] 버튼에 dwell time 동안 응시 | 여가 화면에서 **대화하기 화면**(`/patient/talk`)으로 자동 이동. 현재 시청 중이던 영상 정보(URL, 재생 위치)를 저장하여 복귀 시 사용 |
| 4 | **환자 앱 — 대화하기 화면** | 보호자 메시지("오렌지 주스 마실래?")가 좌측에 표시됨 | 보호자 메시지 기반으로 AI 추천 서버(`POST /recommend/category`)가 호출되어, 맥락에 맞는 **추천 응답 카드 3개**가 화면에 표시됨 (예: "응 마실래", "아니 괜찮아", "나중에") |
| 5 | **환자 앱 — 대화하기 화면** | 환자가 추천 카드 중 하나를 시선으로 선택 | 선택된 응답이 메시지로 전송됨. TTS가 활성화된 경우 환자 맞춤 목소리로 음성 출력 |
| 3-B | **환자 앱 — 팝업 [아니오] 선택** | 환자가 시선으로 [아니오] 버튼에 dwell time 동안 응시 | 팝업이 닫히고 유튜브 시청이 중단 없이 계속됨. 메시지는 대화하기 화면에 쌓여 있어 나중에 확인 가능 |

### MOVE_P_002 — 채팅 종료 후 여가 복귀

> **진입 조건:** 대화하기 화면에서 대화가 종료된 시점 (MOVE_P_001에서 이어짐)

| 단계 | 화면 | 실행 동작 | 상세 설명 |
|------|------|-----------|-----------|
| 1 | **환자 앱 — 대화하기 화면** | 대화 종료 시점에 팝업 표시 | 팝업 내용: **"직전 시청하던 콘텐츠로 돌아가시겠습니까?"** 환자의 시선 선택을 기다림 |
| 2-A | **환자 앱 — 팝업 [예] 선택** | 환자가 시선으로 [예] 버튼에 dwell time 동안 응시 | 직전에 저장해둔 영상 정보를 기반으로 **유튜브 여가 화면**으로 자동 복귀. 이전에 시청하던 영상이 이어서 재생됨 |
| 2-B | **환자 앱 — 팝업 [아니오] 선택** | 환자가 시선으로 [아니오] 버튼에 dwell time 동안 응시 | 팝업이 닫히고 대화하기 화면에 그대로 잔류. 환자가 원할 때 메인 화면을 통해 다른 기능으로 이동 가능 |

### MOVE_P_005 — SOS 호출 기능

> **진입 조건:** 환자가 영상을 시청하고 있는 상태

| 단계 | 화면 | 실행 동작 | 상세 설명 |
|------|------|-----------|-----------|
| 1 | **환자 앱 — 여가(유튜브) 화면** | 환자가 영상을 시청 중 | 시선 추적이 활성화된 상태. 화면 하단/측면에 메뉴 접근 영역이 있음 |
| 2 | **환자 앱 — 메인 화면** | 환자가 **대화** 메뉴를 시선으로 선택 | 대화하기 화면(`/patient/talk`)으로 이동 |
| 3 | **환자 앱 — 대화하기 화면** | 환자가 **몸과마음** 버튼을 시선으로 선택 | 몸과마음 화면(`/patient/body-mind`)으로 이동. 신체/감정 상태를 표현할 수 있는 카테고리 목록이 표시됨 |
| 4 | **환자 앱 — 몸과마음 화면** | 환자가 **"숨막혀"** 표현을 시선으로 선택 후 전송 | 선택된 표현이 보호자에게 메시지로 전송됨(`POST /api/v1/messages`, content_type: EXPRESSION). WebSocket + FCM 푸시로 보호자에게 즉시 전달 |
| 5 | **환자 앱 — 대화하기 화면** | 환자가 **SOS 호출** 버튼을 시선으로 선택 | SOS 호출이 트리거됨(`POST /api/v1/calls`, type: SOS). 화면에 호출 오버레이가 표시되며 전송 중 스피너 표시 |
| 6 | **환자 앱 — SOS 오버레이** | "SOS 응급 호출이 전송되었습니다" 메시지 표시 | 백엔드에서 FCM 긴급 푸시 알림을 보호자 디바이스로 발송. 호출 상태: PENDING. 30초 쿨다운 시작 |
| 7 | **보호자 앱 — 알림 수신** | 보호자 디바이스에 **SOS 긴급 알림** 표시 | FCM 푸시 알림: "환자가 SOS 호출을 보냈습니다". 보호자가 알림을 탭하면 앱 내 호출 상세 화면으로 이동 |
| 8 | **보호자** | 보호자가 알림 확인 후 환자에게 도착 | 호출 상태가 RECEIVED로 업데이트됨(`PATCH /api/v1/calls/{id}/status`) |
| 9 | **보호자 앱 — 채팅 화면** | 보호자가 환자에게 음성 메시지 또는 텍스트 전송 | 보호자가 보낸 메시지가 환자 화면에 표시됨 |
| 10 | **환자 앱 — 대화하기 화면** | **TTS 음성 출력** — 환자 맞춤 목소리로 보호자 메시지 읽어줌 | RunPod TTS 서버(`POST /synthesize`)에서 XTTS v2 모델로 음성 합성. 보호자가 사전 등록한 환자 레퍼런스 음성 기반으로 환자 고유의 목소리로 변환하여 스피커로 출력 |
